# 首页「选择地图」功能 · 实施计划

## Context（背景与目标）

用户要求：在网页首页菜单增加一个新控件「选择地图」，让玩家在**现有老地图（索姆河无人区）**与
**`C:\Users\motia\Downloads\new map\cs_italy_with_real_light.glb`（cs_italy 小镇）**之间选择；
选好后点击「单人模式 / 多人模式」即以该地图开局。

用户已确认的范围：
- 碰撞：**自动生成碰撞盒**（离线脚本从 GLB 三角面提取几何，体素化后合并成 AABB），允许个别瑕疵。
- 多人：**地图投票**，票数最高者胜出；并列第一则随机选一张。
- 出生点 / AI 导航点：自动生成。

> 探查结论：`shared/map.json` 里的 `navPoints` 目前**被 `combat.py` 读取但从未被任何代码使用**
> （`server/bots.py` 用纯转向 steering，不做寻路）。因此**不需要**生成导航点，
> 新地图 JSON 里保留空 `navPoints` 即可。

## 现状分析（Phase 1 探查结果）

### 地图数据流
- `shared/map.json` 是唯一地图数据源，结构：`name / nameEn / bounds{minX,maxX,minZ,maxZ} / groundY /
  style{skyTop,skyBottom,fog,fogNear,fogFar,sunColor,ambientColor,mud} / spawns{"0":[...],"1":[...]} /
  boxes[{x,y,z,w,h,d,t}] / decor[] / navPoints[]`。
- [combat.py](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/server/combat.py#L21-L40)
  在 **import 时**把 map.json 读成模块级全局常量 `MAP_DATA/BOXES/SOLID/GROUND_Y/BOUNDS/SPAWNS/NAV/DECOR`。
  `blocked() / resolve_move() / random_spawn() / ray_world() / has_line_of_sight()` 全部直接读这些全局。
- [server.py](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/server/server.py#L183-L227)
  的 `Lobby` 持有**唯一一个全局 `Match`**（不是多房间），`welcome` 里硬编码 `"map": "/shared/map.json"`。
- [game.py](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/server/game.py) 在
  `add_player/_spawn/_on_input/_on_ability` 里直接读 `BOUNDS`、`GROUND_Y`，并把出生朝向
  **硬编码为 `0.0 if team == 0 else 180.0`**（即「team0 在 -X 朝 +X」的老地图约定）。
- 客户端 [config.js](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/public/js/config.js)
  只 fetch 固定的 `/shared/map.json`；[main.js](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/public/js/main.js#L79)
  在 `boot()` 里一次性 `new World(app.scene, app.data.map, app.data.combat)`。
- [map.js](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/public/js/map.js) 的 `World`
  按 `boxes[].t` 程序化建几何、读 `style` 建天空/雾/灯光，**没有 dispose，也没有按 id 换图机制**。

### 关键约束
- 引擎（服务端 + 客户端）是**纯平地碰撞**：`_on_input` 把 `ny` 钳制在 `GROUND_Y-0.05 .. GROUND_Y+1.6`，
  出生 `pos=[x, GROUND_Y, z]`，`blocked()` 只判断「高度超过 0.65m 台阶」的盒子。
  → 玩家**永远站不到盒子顶上**，只有地面层障碍生效。这是本方案「只做地面层碰撞」的依据。
- 菜单 `#screen-menu` 的 `.menu-bg` 是**不透明**背景，3D 场景在菜单里不可见
  → World 可以延迟到部署时才构建，不必在 boot 时建。
- PowerShell 不支持 `&&`；`git`/`node` 不在 PATH；`python` 可用（服务端用 `python server/server.py` 启动）。
- 新地图资产：`cs_italy_with_real_light.glb` = 92,228,140 字节，glTF 2.0，
  `extensionsUsed=['KHR_materials_unlit']`（three GLTFLoader 支持），**无 Draco/meshopt**，
  14 meshes / 36,915 三角面（几何很轻，体积来自内嵌贴图），原始 VEC3 bbox
  `min[-1664, -4016.34, -1] max[1168, 1135.66, 1908.80]` → **Z-up**，Source 单位（英寸，≈0.0254 m/unit），
  水平约 72m × 131m。`GLTFLoader` 在 `public/vendor/loaders/GLTFLoader.js`。

## 方案总览

1. 新增**地图注册表** `shared/maps.json`（客户端菜单与 Python 服务端共用的唯一清单）。
2. 新增**离线脚本** `tools/build_map.py`：解析 GLB → 转 Y-up/缩放 → 体素化地面层 → 生成
   `shared/maps/cs_italy.json`（boxes/bounds/spawns/style）。
3. 拷贝新地图模型到 `public/models/maps/cs_italy.glb`。
4. **服务端**：`combat.py` 从「import 期常量」改为「可切换的当前地图」（`set_map(id)` 原地替换模块全局）；
   `Lobby` 记录投票、在**每局结束后的 10 秒间歇**结算投票并换图；`welcome` 与新增的 `map` 广播消息下发地图 id。
5. **客户端**：菜单新增地图卡片选择器；`World` 支持 GLB 场景地图 + `dispose()`；`onWelcome` 变为
   「先按 `mapId` 装载地图 → 再进入战斗」；支持运行中收到 `map` 消息换图重建。
6. `net.join()` / `hud` 增加地图字段与控件。

### 关键决策
- **换图时机**：每局结束 → `phase` 由 `ended` 回到 `live` 的那一刻结算一次投票，票多者作为下一局地图；
  并列第一随机取一张。一局之内地图不变，玩家不会被中途传送。
- **房间冷启动**：`Lobby.sockets` 为空时，第一个加入者的选择**立即**成为当前地图（唯一真人 / 单人模式即
  等于「我的选择就是地图」）。
- **垂直可玩性**：只生成**地面层**碰撞盒。建筑需从门口进入；楼梯与二楼不可达（会被当作封闭体/被忽略）。
- **坐标轴**：以新地图水平方向较长的轴（本次为世界 Z，约 131m）作为队伍分离轴，
  team0 在 min 端、team1 在 max 端，`yaw` 由出生点自带（不再硬编码 0/180）。

## 详细改动

### 1. 新增 `shared/maps.json`（地图注册表）

```json
{
  "default": "somme",
  "maps": [
    {
      "id": "somme",
      "name": "索姆河无人区",
      "nameEn": "Somme No Man's Land",
      "desc": "1916 · 战壕与无人区",
      "file": "/shared/map.json",
      "scene": null
    },
    {
      "id": "italy",
      "name": "意大利小镇",
      "nameEn": "Italy Town",
      "desc": "地中海小镇 · 街巷近战",
      "file": "/shared/maps/cs_italy.json",
      "scene": {
        "model": "/models/maps/cs_italy.glb",
        "rotX": -90,
        "scale": 0.0254,
        "offset": [0, 0, 0]
      }
    }
  ]
}
```

- `file`：该地图的 JSON 数据（bounds/boxes/spawns/style），服务端与客户端都按此 URL 取。
- `scene`：非 null 表示「模型地图」，客户端用 GLB 渲染；null 表示「程序化盒子地图」（沿用现有 `_build()`）。
- `scene.rotX/scale/offset` 是**调参入口**：模型朝向/大小不对时只改注册表，不改代码。

### 2. 新增 `tools/build_map.py`（离线碰撞/出生点生成）

纯标准库（`json/struct/math`），无第三方依赖。输入 `cs_italy_with_real_light.glb`，输出
`shared/maps/cs_italy.json`。步骤：

1. **解析 GLB**：校验 `magic == b"glTF"`，遍历 chunk，取 JSON chunk（`0x4E4F534A`）与 BIN chunk（`0x004E4942`）。
2. **遍历场景图**累积节点世界矩阵**，对有 mesh 的节点取每个 primitive（`mode == 4` TRIANGLES）：
   读 `POSITION`（VEC3/FLOAT/5126）与 `indices`（SCALAR/5123|5125）；支持 `bufferView.byteStride`；跳过 `sparse`。
3. **坐标转换**：`(x, y, z) → (x, z, -y)`（Z-up → Y-up，等价于 `rotation.x = -90°`），再乘 `SCALE = 0.0254`。
   然后**水平方向重定心**（减去水平 bbox 中心）并**把最低点抬到 y=0**（`GROUND_Y = 0`）。
4. **体素化（地面层）**：`CELL = 1.0`m。
   - 对每个三角形，取其水平投影 AABB 覆盖的格子；用**格子正方形 vs 三角形 2D 投影的 SAT 相交测试**
     判断是否覆盖该格（避免 AABB 在对角线上过度覆盖）。
   - 只统计**地面层几何**：三角形的 `minY <= GROUND_Y + 1.2`（排除二楼楼板/屋顶）。
   - 每格记录 `top = max(该格地面层几何的 Y)`。若 `top > GROUND_Y + 0.65`（超过可跨越台阶高度）→ 该格为实体。
   - 若实体格总数导致合并后盒子数 `> 3000`，把 `CELL` 提到 `2.0` 重跑一次（控制客户端 `blocked()` 的 O(n) 开销）。
5. **合并**：按高度量化到 0.5m 分桶，桶内做贪心矩形合并（先沿 X 合并连续 run，再纵向合并等长 run），
   产出 `boxes[]`：`{x, y: GROUND_Y + h/2, z, w, h, d, t: "wall"}`。
6. **地面盒**：`{x: cx, y: GROUND_Y - 1, z: cz, w: W + 4, h: 2, d: D + 4, t: "ground"}`。
7. **出生点自动生成**：取水平方向较长轴为队伍分离轴。
   - team0 条带 = min 端向内 12m；team1 条带 = max 端向内 12m。
   - 在条带内收集**可行走格**中心，沿垂直轴按 20% / 50% / 80% 分位各取 1 个，并吸附到最近可行走格
     （若某分位找不到，向条带中心回退）。
   - 每点写 `{x, y: GROUND_Y + 0.1, z, yaw}`；`yaw`：team0 朝 +较长轴、team1 朝 -较长轴
     （例：较长轴为 +Z → team0 `yaw=90`，team1 `yaw=270`；+X → 0 / 180）。
8. **其他字段**：`name:"意大利小镇" / nameEn:"Italy Town" / note`（写明自动生成、只覆盖地面层）、
   `bounds`（水平 bbox 各加 1m 余量）、`groundY: 0`、`style`（地中海日间：亮蓝天空、暖雾、`fogNear/ fogFar`
   按地图尺寸给，`sunColor/ambientColor` 可给中性值，因为 `KHR_materials_unlit` 材质不受光照影响）、
   `decor: []`、`navPoints: []`。
9. 结束时打印：盒子数、bounds、出生点、三角形数，便于人工核对。

## 假设与决策

| 项 | 决定 | 理由 |
|---|---|---|
| 多人换图时机 | 每局结束的 10 秒间歇结算一次投票 | 不打断进行中的对局；并列随机满足用户要求 |
| 冷启动 | 房间为空时第一个加入者的选择立即生效 | 单人模式 = 我的选择就是地图；两标签页时先到者定图 |
| 投票统计范围 | 仅统计**当前连接的真人**（离开即失效） | 机器人不投票 |
| 垂直可玩性 | 只生成地面层碰撞；楼梯/二楼不可达 | 服务端是平地引擎，加高度支持会波及索姆河地图的命中判定 |
| 导航点 | 不生成（保留空数组） | `bots.py` 用 steering，`navPoints` 是死代码 |
| 出生朝向 | 出生点自带 `yaw`，弃用硬编码 0/180 | 新地图队伍分离轴是 Z，不是 X |
| 模型调参 | `rotX/scale/offset` 放在注册表里 | 朝向/大小不对时只改 JSON，不改代码 |
| 92MB 模型 | 直接拷贝进 `public/models/maps/`，加载时显示遮罩 | 用户指定使用该文件；本地静态服务无压力 |

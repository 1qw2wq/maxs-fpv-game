# 地图选择、共享数据与运行边界

## 可用地图

| ID | 地图 | 特点 |
| --- | --- | --- |
| `somme` | 索姆河无人区 | 战壕、掩体与无人区 |
| `italy` | 意大利小镇 | 上传场景与街巷近战 |
| `proc_city` | 程序化旧城 | 240×240 米、128 栋相连建筑、小巷、多层室内与中心公园 |

注册表 [maps.json](../../public/shared/maps.json)指定地图碰撞文件、可选场景、据点及推荐参数。旧城单人推荐 15 个 AI；显式的每图数量会被记住。联机默认零 AI，可由房主配置。

## 选择与权威

单人在主页选择地图/规则，选好角色装备后部署。联机地图/规则由房主控制，客人跟随房主配置；房主在主页审批，客人准备后由房主统一开始。地图/AI 等启动配置在开始阶段锁定，不在运行中偷偷替换碰撞。

Python、浏览器 Pyodide 与 JavaScript 使用同一份已提交地图数据。画面开口、门框、楼板与权威碰撞须一致；不能只改元数据就声称打通墙体。墙壁阻挡子弹，旧城楼梯使用连续坡面及真实上层开口，而非逐块木板碰撞。

## 开发与验证

旧城生成器仅用于可选创作，不是部署构建步骤：

```sh
node tools/generate-proc-city.mjs 1942
node tools/test-proc-city.mjs
node tools/test-city-openings.mjs
python tools/test-proc-city.py
STAIR_JS_PARITY=1 python tools/test-stairs.py
```

生成后需同步检查几何、开口、路线和规范种子产物，并启动新对局加载。旧房间保留其主机已加载的地图；不要为更新静态文件而让运行中的碰撞各自变化。

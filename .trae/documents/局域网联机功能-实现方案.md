# 局域网联机功能 · 实现方案

## Context（背景与目标）

联机对战逻辑其实**已经完整**：WebSocket 帧同步、队伍分配、32 人上限、地图投票、AI 补位机器人都在跑，同一台机器开两个标签页就能对战。真正缺的只有「让局域网里另一台设备连得进来」这一环：

- [server.py](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/server/server.py#L35) 里 `HOST = "127.0.0.1"` 只监听回环地址，同学从自己电脑访问房主的 IP 会被直接拒掉。
- 客户端 [main.js](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/public/js/main.js#L237-L238) 用的是 `location.host`，所以只要浏览器打开的是房主地址，就天然连对 —— 无需改协议。
- [README.md](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/README.md#L28-L38) 目前的做法是「让用户自己去源码里把手改成 `0.0.0.0` 再重启」，这不该是交付形态。

目标：**开箱即用的局域网联机** —— 房主运行服务端后，终端直接打印出可分享的局域网地址；同学用浏览器打开该地址即可加入；并提供「服务器地址」输入框作为端口顺延/地址异常时的手动纠正手段；文档与界面提示同步更新。

## 改动清单

### 1. server/server.py（核心）

- `HOST = "127.0.0.1"` → `HOST = "0.0.0.0"`，监听所有网卡（Windows 下同时覆盖 `127.0.0.1`，本机访问不受影响，双标签页流程不破）。端口顺延扫描 `range(START_PORT, START_PORT + 20)` 与 `except OSError` 逻辑保持不变。
- 新增 `lan_ips()`，纯标准库（`socket` + `ipaddress`），**不引入新依赖**：
  - 用 UDP `connect(("8.8.8.8", 80))` 取默认出口网卡地址（UDP connect 不发包，只做选路），**排在最前**；
  - 再并入 `socket.getaddrinfo(socket.gethostname(), None, socket.AF_INET)` 的结果（补上多网卡的第二、第三条）；
  - 用 `ipaddress` 过滤掉回环、`0.0.0.0`、`169.254.*` 链路本地地址，去重保序；
  - 全程 `try/except`，离线或无网卡时返回空列表 —— 服务端必须照常启动。
  - 说明：Hyper-V / VMware / WSL 的虚拟网卡（172.x 等）无法在代码层可靠区分，因此**宁可与真实地址一起列出**，由用户对照 `ipconfig` 挑选，也好过只给一条自信而错误的地址。
- `main()` 的启动日志（**保持纯 ASCII** —— 控制台可能是 GBK，沿用现有 `log()` 而不是新起 `print`）：
  - 保留 `[trench] ready -> http://127.0.0.1:<port>`；
  - 每条局域网地址打印一行 `[trench] LAN   -> http://<ip>:<port>`；
  - 追加一行 `[trench] share the LAN url above; allow python through the firewall if asked`；
  - 末尾那句 `print("Serving on http://%s:%d" ...)` 同步改成回环地址，避免打印出不可用的 `http://0.0.0.0:<port>`。

### 2. public/index.html

  `<label class="field"><span>服务器地址</span><input id="input-server" type="text" placeholder="留空 = 自动（当前页面地址）" autocomplete="off"></label>`
- 其后新增一行 `<p class="hint dim">`：说明「房主运行服务端，把终端打印的 `http://<局域网IP>:端口` 发给同学；地址异常时可在上面手动填写」。
- 更新第 74 行既有提示，把「多开两个标签页即可对战」扩展为同时覆盖局域网玩法。

### 3. public/js/hud.js

- 构造函数 `el` 增加 `server: $('input-server')`。
- 仿照既有 `get playerName()`（[hud.js:92](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/public/js/hud.js#L92-L94)）新增 `get serverAddress()`，返回输入框去空格后的原文（归一化交给 main.js，Hud 不做 URL 逻辑）。
- 新增 `setServerAddress(v)` 用于回填 `tf.server`。
- **不改 `bindMenu(...)` 参数表**；Enter 触发仍只绑在 `#input-name`。

### 4. public/js/main.js

- 新增 `normalizeServer(raw)`：空 → `location.host`；裸 `IP`/`host` 先补 `http://` 再交给 `new URL()`（**不要手写 `split(':')`**，IPv6 会断）；IPv6 主机用 `[...]` 包裹；**缺端口时补 `location.port || '8080'`**（否则默认落到 80 端口）；解析失败抛错交给 `menuError`。需覆盖：空 / `192.168.1.23` / `host:port` / `http://x:p/` / `x:p/ws` / `[fe80::1]:p` / 尾斜杠。
- 改造 `deploy(opts)`（[main.js:235-265](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/public/js/main.js#L235-L265)）：
  - 用 `normalizeServer(app.hud.serverAddress)` 拼 `ws://<host:port>/ws`；
  - **地址变化必须重连**：现有 `if (!app.net.connected)` 意味着「已连接后再改地址不生效」。改为记录实际连接地址（新增 `app.netUrl`），地址不同时先 `app.net.close()` 再重建 `Net` 重连；把 `new Net({...})` 的 handler 对象提成可复用的工厂函数，避免重复代码块；
  - 连接失败时 `app.net.close()` 释放半死 socket，并让 `menuError` **回显实际尝试的 `host:port`** —— 这是局域网排查时最有用的一条信息。
- `setupMenu()` 中回填 `tf.server`（读不到或为空则留空），玩家修改后写回 `localStorage['tf.server']`（与 `tf.mapId` / `tf.skinId` 同族命名）。

### 5. README.md

- 重写「运行」与「局域网联机」两节：说明默认已监听所有网卡；贴出 `ready ->` / `LAN   ->` 两行示例日志；告诉用户把 LAN 地址发给同学；写明 **Windows 防火墙首次弹窗必须点「允许」**（点取消会导致入站全部被拦，这是「连不上」最常见的原因）；提示校园网/公共热点可能存在 AP 隔离（设备间互相不可见），此时改用房主自建热点；说明「服务器地址」输入框「留空 = 自动」的行为。
- 补一句安全提示：绑定所有网卡后，免鉴权的角色上传接口（24MB）对同一网段开放。
- 顺手修正过时按键表：改为 `Shift` = 蹲下，删掉「冲刺」行与 `Ctrl/C` 蹲下那行（上一轮已改键位，README 未同步）。

## 验证（单机模拟局域网客户端）

本机只有一台设备，用「访问自己的局域网 IP」来模拟局域网客户端：

1. 重启服务端，确认日志同时出现 `ready -> http://127.0.0.1:<port>` 与至少一条 `LAN -> http://192.168.x.x:<port>`。
2. **HTTP 链路**：浏览器打开 `http://<局域网IP>:<port>`（**不是** 127.0.0.1），能进主菜单 → 证明绑全网卡与防火墙均通过。
3. **WS 链路**：在该页面用「多人模式」部署，DevTools → Network → WS 应看到 `ws://<局域网IP>:<port>/ws` 返回 101；同时用另一个 127.0.0.1 标签页进入，两页能互相看到对方角色（同一进程，等价于真联机）。
4. **服务器地址输入框**：
   - 正向：在 127.0.0.1 页面填 `<局域网IP>`（不带端口）仍能连上 → 证明补端口逻辑生效；再试 `:端口`、`http://ip:port/`、`ip:port/ws`。
   - **反向（关键）**：填 `127.0.0.1:9` 必须**立刻失败**且 `#menu-error` 显示该地址 —— 否则只是「自己连自己」，证明不了字段生效；清空后应回落 `location.host`。
   - 用浏览器自动化完成上述两步并读取 `#menu-error` 文本。
5. **回归**：确认 Shift 蹲下、地图选择、单人模式机器人补位等既有功能不受影响（服务端只改了绑定地址与日志）。

## 不做的事（避免过度设计）

- 不加鉴权、不做 UDP 广播自动发现、不做地址历史 / 连通性测试按钮 / 保存重连面板。
- 不引入任何新依赖（`socket`、`ipaddress` 均为标准库）。

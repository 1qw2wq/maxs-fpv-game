# 本地、局域网与静态站点联机参考

## 运行站点

可直接使用部署好的静态站点；本地可选 Python 3.10+ 服务：

```sh
pip install -r requirements.txt
python server/server.py --open
```

打开终端打印的地址，通常为 `http://127.0.0.1:8080`；局域网其他设备使用打印的 LAN 地址，而不是它们自己的 localhost 或 `0.0.0.0`。Windows 可运行[启动服务器.bat](../../启动服务器.bat)。防火墙须允许入站；校园/访客 Wi-Fi 的 AP 隔离可能阻止互访，必要时换可互通网络。Python 服务是可选项，Vercel-only 不依赖它。

## 当前主菜单房间流程

1. 房主创建房间，留在主页审批加入请求并选地图、规则和可选 AI。
2. 同源同存储分区的标签页可输入房间号；不同浏览器/设备逐人交换 WebRTC 邀请与回答。
3. 配对只是建立传输；房主接受后客人自动进入角色/装备选择并准备。
4. 房主选好自己角色后按开始；权威引擎与地图加载完成才统一放行。

当前主菜单使用浏览器权威审批房间；可选 Python 旧房间 API 是独立路径，不要把「能打开 LAN 页面」当作已完成浏览器配对，也不要用保存的服务器地址替换已配对通道。

## 连接边界与排查

房间号/链接不能替不同设备做信令；同一局域网也不保证绕过浏览器分区或防火墙。STUN 只帮助发现地址，不是 TURN 中继；Vercel 不提供任意 NAT 穿透。房主页关闭或被系统完全挂起会影响对局，没有主机迁移。

排查顺序：页面可达 → 传输配对/同分区房间 → 房主批准 → 客人准备 → 房主加载/开始。诊断页 P2P 成功只代表当前浏览器内自检，不证明跨设备成功。

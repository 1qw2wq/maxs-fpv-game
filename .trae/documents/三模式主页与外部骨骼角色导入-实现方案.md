# 三模式主页 + 外部骨骼角色导入 —— 实现方案

## Context（为什么做这次改动）

当前主页只有一个「进入战场」按钮，且 AI 机器人开关与联机共用同一入口，玩家无法区分「我想和真人打」还是「我想单机打 AI」。同时角色系统是硬编码的图元拼装骨架（[character.js](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/public/js/character.js) 文件头注释明确写了 "No skinning, no imported models"），玩家无法使用自己的模型。

用户要求把主页拆成三个模式入口，并新增「导入外部骨骼模型（GLB/GLTF）+ 骨骼映射微调 + 上传服务器共享」的设置模式。已通过 AskUserQuestion 确认三项决策：

1. **设置模式范围** = 导入外部骨骼模型（GLB/GLTF），把模型骨骼映射到游戏关节，并允许骨骼偏移微调。
2. **upload 范围** = 上传到服务器共享，所有玩家都能看到/选用。
3. **机器人默认行为** = 多人模式默认关闭（仍可在模式内手动开），单人模式固定开启。

### 环境硬约束（已实测，务必遵守）

- 本机**无 Node.js/npm**，前端是**无构建**的原生 ES Module + import map（`"three": "./vendor/three.module.js"`），three 锁 **r169**。
- 新增前端依赖只能**直接 vendor 源文件**，不能走包管理器。
- 服务端是 aiohttp 单端口（静态文件 + `/ws`），路由注册顺序敏感。
- `public/vendor/` 目前**只有** `three.module.js`；r169 核心**不含 `GLTFLoader`**（已核验）；但 `SkinnedMesh` / `Bone` / `Skeleton` / `AnimationMixer` 都在核心里。

### 追加需求：左右操作反转（用户反馈，必须先修）

用户反馈：A 应向左移动、D 应向右移动；鼠标左移应视角左转、右移应视角右转——当前**两者都反了**。

**已定位根因（只在 [controls.js](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/public/js/controls.js) 内，2 处）**：

坐标约定为 `forward(yaw) = (cos yaw, 0, sin yaw)`（已核验，与 [combat.py](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/server/combat.py#L63-L68) `dir_from_angles` 及 [character.js](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/public/js/character.js#L503-L505) `yawToRotation` 完全一致）。相机由 [main.js](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/public/js/main.js#L484-L488) `camera.lookAt(eye + aim())` 驱动，`up = +Y`。

在 three.js 右手 Y-up 系里，视线的**屏幕右方** = `cross(forward, up)`；代入 pitch=0 得 `right = (-sin yaw, 0, cos yaw)`。由此：

1. **yaw 增大 = 向右转**（forward 从 +X 转向 +Z）。但 [controls.js:65](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/public/js/controls.js#L65) 是 `this.yaw -= e.movementX * ...`，鼠标右移（`movementX > 0`）反而让 yaw 减小 → **视角左转**。应为 `+=`。
2. [controls.js:161-163](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/public/js/controls.js#L161-L163) 的注释声称 "right = forward rotated -90 deg"，但代码

   ```js
   const wishX = Math.cos(yawRad) * fx + Math.sin(yawRad) * fz;
   const wishZ = Math.sin(yawRad) * fx - Math.cos(yawRad) * fz;
   ```

   中 fz（D 键 = +1）乘的向量是 `(sin yaw, -cos yaw)`，正好等于 `-right`（forward 旋转 +90°），所以 **D 向左、A 向右**。

3. 俯仰（`this.pitch -= e.movementY`）与前后（W=+forward、S=−forward）经核验是**正确**的，不要改动。

**结论**：这是纯客户端输入符号错误，服务端（`_on_input` 移动钳制、`dir_from_angles` 射击方向）与 `aim()` 都无需改动。修 controls.js 即可，**不能**去翻转服务端 yaw 约定（会连带打断命中判定与远端角色朝向）。

`createExternalGirl` 的实现要点：

- 用 `SkeletonUtils` 的方式克隆骨骼（**不引入 SkeletonUtils**，改用 `template.scene.clone(true)` 后手工重建 `Skeleton`：遍历收集克隆体的 `isSkinnedMesh`，对每个用 `new THREE.Skeleton(clonedBones)` 重新绑定并复制 `skeleton.boneInverses`）。这是无 SkeletonUtils 时克隆蒙皮模型的标准做法。
- **绑定期**：对每个已映射的骨骼记录静止姿态 `restQuat`（`bone.quaternion.clone()`）与关节名。

  - `spine`：`crouch * 0.28 + (run ? 0.10 : 0.02)` 前倾；

- 「仅本地保存」→ `localStorage['tf.skin']` 存 `{ name, map, scale, rotY, offsets }` + 把模型二进制存 `IndexedDB`（localStorage 装不下）。**简化为：本地保存只记住映射与变换参数，模型文件仍需上传共享才能跨会话使用**（避免引入 IndexedDB 的复杂度）。
- 「上传共享」→ `POST /api/character`（`FormData`：`meta` 为 JSON 字符串、`model` 为 `File`），成功后刷新 `#rig-shared` 并自动选中该角色。
- 「使用」→ 把 `{ id, name }` 写入 `app.loadout.skin`，主页/兵种页显示当前角色名。

### 5. 服务端：角色存储 + API + skin 透传

#### 5.1 [server/server.py](file:///c:/Users/motia/Documents/trae_projects/FPS%20web%20game%20demo/server/server.py)

- 顶部新增 `CHARS = SHARED / "characters"`。
- `create_app()`：`client_max_size=1 << 25`（32MB，模型上传需要；WS 的 `max_msg_size=8192` 不变）。路由**插在 `/shared/` 静态之前**，仍全部在 catch-all `add_static("/")` 之前：

```python
app.router.add_get("/ws", ws_handler)
app.router.add_post("/api/character", upload_character)
app.router.add_get("/api/characters", list_characters)
app.router.add_static("/shared/", SHARED, show_index=False)
app.router.add_get("/", index)
app.router.add_static("/", PUBLIC, show_index=False)
```

- `upload_character(request)`：
  1. `reader = await request.multipart()`；收集 `meta`（文本）与 `model`（文件）。
  2. 校验 `meta`：`name` 截断 24 字符（空则 `Custom`）；`bones` 必须是 `dict[str,str]`，key 限定在固定关节名白名单内；`scale` 浮点钳到 `[0.2, 5.0]`；`rotY` 钳到 `[-180,180]`；`offsets` 为 `{关节名: [x,y,z]}`，每项钳到 `[-90,90]`。
  3. 校验 `model`：文件名后缀 `.glb/.gltf`；`len(data) <= 24 * 1024 * 1024`；`.glb` 需 `data[:4] == b"glTF"`。
  4. `cid = uuid4().hex[:16]`；写 `CHARS/<cid>/model.glb` 与 `CHARS/<cid>/meta.json`（meta 内含 `id/name/author/file/scale/rotY/bones/offsets/ts`）；`file` 字段为 `/shared/characters/<cid>/model.glb`。
  5. 返回 `{"ok": true, "meta": {...}}`；任何校验失败返回 `{"ok": false, "error": "..."}` + HTTP 400。
- `list_characters(request)`：遍历 `CHARS/*/meta.json`，跳过解析失败项，按 `ts` 倒序返回 `{"characters": [...]}`。
- **不使用 `show_index` 之外的目录扫描**，`CHARS` 用 `mkdir(parents=True, exist_ok=True)` 惰性创建（`add_static` 只要求 `/shared/` 存在）。
- 版本号：`three` 的 `GLTFLoader` 需要在客户端解析，服务端只做字节校验。

## 假设与决策

| 项 | 决策 | 理由 |
| --- | --- | --- |
| 左右反转的修法 | **只改 controls.js 的两处输入符号**，不动服务端 yaw 约定 | 服务端 `dir_from_angles`、`_on_input` 与客户端 `aim()`、`yawToRotation` 四方一致且经核验正确；改约定会同时污染命中判定与远端朝向 |
| 单人模式服务端改动 | **零改动**，只靠 `join.bots=true` | `_pick_team()` + `fill_bots()` 已能产出「真人 + AI 队友 vs AI 敌军」 |
| 多人模式机器人 | 默认 `false`，模式内开关仍可用 | 用户明确选择「多人关、单人锁开」 |
| 机器人数量 | 沿用 4/6/8/12，单人模式也用它 | 用户要求沿用现有选择 |
| 外部模型动画 | 腿/脊柱/头程序化驱动；肩肘腕只用用户偏移量 | 任意骨架的臂轴朝向不可靠，硬套会让手臂扭曲；这也正是「骨骼偏移微调」的用途 |
| 模型格式 | 仅支持未压缩 glTF/GLB（非 Draco/meshopt/KTX2） | 不额外 vendor 解码器，保持无构建 |
| 上传鉴权 | 无（本地 demo），仅做类型/大小/魔数校验 | 与现有「无账号」架构一致 |
| 本地保存 | 只存映射与变换参数到 localStorage | 模型二进制进 localStorage 会超限，避免引入 IndexedDB |
| 上传后可用范围 | 所有玩家可在设置模式里看到并选用；选中后其他人也能看到你 | 「上传到服务器共享」的直接落地 |

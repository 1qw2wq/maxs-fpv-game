# 堑壕前线 Trench Front

一战主题的多人联机 FPS 网页小游戏，提供团队死斗与据点控制规则。四个兵种（突击兵 / 医疗兵 / 支援兵 / 侦察兵），
共 **30 把武器：26 把兵种主武器与 4 把通用副武器**，全部可操纵角色为**二次元风格美少女**（半写实比例，约 5.7 头身）。

无构建步骤：前端是原生 ES Module + import map，后端是单个 Python 进程同时提供静态文件与 WebSocket。
**也可以完全没有后端**：纯静态托管（Vercel / 任何静态服务器）时，浏览器的内嵌 Python（Pyodide）
会跑起同一份服务端代码，单机 + 机器人对局照常进行——见「部署 → Vercel」。

> English documentation: **[README.en.md](README.en.md)**.

### 当前版本概览

- **三张地图**：索姆河、意大利小镇、240×240 米程序化旧城。旧城包含 128 栋可进入建筑、中心公园、
  七种共 8 辆车辆，单机默认 **15 个机器人**。
- 主武器数量：**突击 6 / 医疗 5 / 支援 6 / 侦察 9**；所有兵种均可另选 APX Carry、G17、沙漠之鹰或信号枪，
  主副武器弹药独立保存。
- 电脑使用原生鼠标锁定，手机使用独立摇杆/按钮模式；不会启用光标边缘转向。
- **单人/多人可选 AI 难度**：简单、普通、困难、专家和混合编队；多人房主可添加 0–16 个 AI，客人遵循房主设置。
  详见[难度、战术与回归检查](docs/bot-difficulty.md)。
- **统一作战室界面**：主菜单、配装、设置、新手指引、对局子菜单与开发工具采用橄榄绿/深炭色/琥珀色风格，
  支持响应式布局与键盘选枪。
- **诊断状态修正**：`/debug.html` 独立运行；此页没有游戏运行状态是正常现象，不代表 `main.js` 启动失败。
  详见[诊断与游戏启动排查](#诊断与游戏启动排查)。
- 最新楼梯修复按碰撞子步跟随可行走表面，并按斜板真实底面检查头顶空间，详见[楼梯可靠性与头顶空间](#楼梯可靠性与头顶空间)。

## 界面语言（中文 / English）

整个界面都是双语的，随时可切换：

| 位置 | 作用 |
| --- | --- |
| 主菜单右上角的 **EN / 中文 按钮** | 一键切换整个界面，立即生效 |
| **「设置模式」里的「界面语言」** | 同样的切换，旁边就是角色模型工具 |
| 网址加 `?lang=en` / `?lang=zh` | 本次访问强制使用该语言 |
| 什么都不做 | 第一次访问跟随浏览器：中文浏览器用中文，其它用英文 |

选择会记在 `localStorage` 的 `tf.lang` 里，下次打开继续用。武器、兵种、队伍、地图的名字与说明
也一起翻译（数据文件里 `name` / `nameEn`、`desc` / `descEn` 成对存在），
兵种与武器卡片**第二行固定显示另一种语言的写法**，两种拼写始终同屏可见。
切回中文后与中文用户看到的内容逐字一致。

## 运行

需要 **Python 3.10+** 与 **aiohttp**（不需要 Node.js，也没有任何打包步骤）。

**推荐：直接双击项目根目录里的 `启动服务器.bat`。** 它会自己装好 aiohttp（首次）、启动服务器、
**并自动用默认浏览器打开游戏页面**，不需要手输网址。它同时把本机地址与局域网地址打印在一个独立的
命令行窗口里。这个窗口和编辑器（TRAE / VS Code）完全无关，
**关掉编辑器也不会让服务器停止**——只有关闭那个命令行窗口、或按 `Ctrl+C` 才会停。
想长期开着让同学联机，就双击它，不要依赖编辑器里的「运行」。
（端口被占用自动顺延时，打开的也是顺延后的正确地址，因为网址由服务器自己给出。）

手动运行（等价，`--open` 可选，加了就自动开浏览器）：

```bash
pip install aiohttp
python server/server.py --open
```

启动后会打印本机地址，以及可以发给别人的局域网地址：

```
[trench] ready -> http://127.0.0.1:8080
[trench] LAN   -> http://192.168.1.23:8080
[trench] share the LAN url above; allow python through the firewall if asked
```

本机用浏览器打开 `http://127.0.0.1:8080` 即可。默认端口是 8080，若被占用会自动顺延到
8081、8082……（**终端里打印的才是实际端口**）。按 `Ctrl+C` 停止。

### 局域网联机与房号

服务端默认监听所有网卡，所以同一局域网里的**其它设备直接用浏览器打开终端打印的那条 `LAN`
地址**（形如 `http://192.168.1.23:8080`）就能打开游戏，不需要任何额外配置。

**下面的分组、回收与容量规则描述可选 Python 服务端的旧协议/API。主菜单多人按钮现在统一使用下一节的浏览器房主审批大厅，不会把大厅转交给填写的服务器地址；不同设备仍需邀请码配对。**

旧服务端协议按**房号（8 位数字）**分组，互不干扰：

- **自己创建房间**：点「创建房间」，服务器分配一个 8 位房号，HUD 右上角一直显示这个房号
  （`1958 0121` 这样分组显示，方便念给同学听）。把这个号发给大家即可。
- **加入房间**：点「加入房间」，填房主的 8 位房号（空格可省略），确认后才会开局；
  房号不存在会直接提示「房号不存在」，不会被塞进别人的房间。
- 主菜单会记住最近进过的房号，一键重进；页面上还列着当前**公开的房间**（人数 / 地图 / 阶段）。
- 同一房号里的玩家才会互相看见、互相打；不同房号的比赛完全隔离，比分和计分板也各自独立。
- 服务器同一时间只跑一张地图（`public/engine/combat.py` 只有一份世界状态）。如果别的房间正在另一张图上对局，
  你选的地图这一局会先让位——这时画面顶部会直接说明「「意大利小镇」正被其他房间占用，本局是「索姆河无人区」」，
  而不是默默换图。两个房间都停下后，下一局就会用上你选的地图。
- 房主离开、房间空掉之后，多人房号保留 2 分钟（够刷新页面重新进），单人练习房 15 秒就回收；
  房间满了（上限 24 间）时服务器会先回收最久没人用的空房间，而不是把人挡在门外——
  只有 24 间**都有真人**时才会提示「服务器上房间太多了，稍后再试」。

- **Windows 防火墙**：首次运行会弹出「是否允许 Python 访问网络」，必须点**允许**；
  点了取消会让外部设备完全连不进来，这是「同学连不上」最常见的原因。补救办法是到
  「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」里勾上 Python。
- 终端会列出**所有**非回环 IPv4 地址：装了 VMware / Hyper-V / WSL 的机器会多出虚拟网卡地址。
  请对照 `ipconfig` 里「无线局域网适配器 WLAN」或「以太网适配器」的那条，把正确的地址发给同学。
- 校园网、公共热点常开启 **AP 隔离**（同一网络下的设备彼此不可见）。遇到这种情况，让房主用
  电脑自建热点，同学先连热点，再打开上面那条地址。
- 端口被占用顺延时，记得把**实际端口**一起告诉同学（如 `http://192.168.1.23:8081`）。
- 主菜单新增的**「服务器地址」留空即自动**——自动连接当前页面的地址，这也是最常见的情况。
  只有在端口顺延后用旧地址、或同学打开的是自己电脑上的本地副本时，才需要手动填写房主的
  `IP` 或 `IP:端口`；填错时菜单下方会显示实际尝试连接的地址，方便排查。
- 安全提示：监听所有网卡后，免鉴权的角色模型上传接口（单文件上限 24MB）对同一网段的所有人开放，
  不要在不可信的网络上长期开着。
- 同一台机器开两个浏览器标签页也完全可以对局。

### 网页版联机（部署到 Vercel 等静态托管时，完全不需要服务器）

静态托管上没有任何服务端进程，但**多人照样能直接玩**：房间由**创建房间的那个玩家**在自己的
浏览器里运行（用的还是单机那套页内 Pyodide 引擎），其他人直接连到他。全程**不经过任何第三方
服务**——没有中转、没有账号、没有 key：

- **同一个浏览器多开标签页**：点「创建房间」后，把 8 位房号告诉另一个标签页，用「输入房号加入」
  填进去 →「申请加入」→ 等房主在主页面接受。两个标签页必须使用**同一来源、同一浏览器存储分区**（不能混用不同 Vercel
  部署网址或普通/无痕窗口），通过 `BroadcastChannel` 通信。
- **不同的电脑**：用「邀请朋友」。房主点「生成邀请码」（`TFi1.` 开头的一大段文本），把它发给
  朋友；朋友的页面「用邀请码加入」→ 粘进去 → 得到回答码（`TFa1.` 开头），把回答码发回房主，
  房主粘进同一个框点「完成配对」。两页之间就建立了一条**点对点 WebRTC 直连**（`js/p2p.js`），
  对局数据只走这条直连。**只有数据通道真正打开后，才会显示配对成功；配对不等于获准加入**。
  完成配对后，房主回主页面接受申请。每位朋友需要单独的邀请码；客人不再各自点部署。
  完全不使用外部服务时，需要网络允许直连（通常是同一局域网或可访问的公网地址）。不同家庭网络可由
  **双方在生成各自代码前**开启「跨网络」，使用可选的外部 STUN 服务发现地址，但这不能保证连接成功。
  对称 NAT、UDP 封锁或严格防火墙仍可能需要 **TURN 中转**，而 **Vercel 本身不提供 TURN**；
  仅靠 Vercel 无法保证这些网络之间能够联机。
- **房主审批与统一开始**：创建房间后**留在主页面**，可查看玩家名字、接受/拒绝加入申请，并选择地图与规则。
  获准玩家**自动进入角色选择**，选主武器、副武器后点「准备」。房主点「选择角色」配置自己；
  所有获准玩家准备后，房主的「开始游戏」才可点击。房主地图载入完成后，**所有获准玩家自动进入同一局**，
  不要求客人再次点击部署。客人不能修改地图或规则；改角色/主副武器、返回主菜单会取消准备。
  等待玩家可「离开房间」；拒绝、关闭或超时会给明确提示。引擎启动失败可在同一大厅重试。
  已开始后不再接受**新会话**，未接受的申请会收到提示；已获准的同一会话丢失座位仍可自动重进。
  刷新页面是新会话，需要房主重新建大厅并审批。桌面自动进入后仍须点击游戏画面取得原生鼠标锁定。
  详见 [审批大厅与同步开始](docs/host-approved-lobby.md)。
- **创建房间立刻就有房号**：点「创建房间」的瞬间就生成房号（不再等页内引擎启动），房号同时显示在
  HUD 右上角和「选择兵种」页面顶部；**点一下右上角的房号会复制邀请链接**（形如
  `https://你的站点/?code=1958 0121`），朋友打开后自动填入房号。短房号/链接只支持同一浏览器存储分区
  内的标签页直接加入；跨电脑仍需交换邀请码和回答码。
- **房主的浏览器就是这一局的权威**：命中、计分、复活、地图都在房主那边判定，其他人只是客户端。
  因此**每个房主都能选自己的地图，多个房间可以同时跑不同的地图**——这是自建服务端做不到的
  （`combat.py` 每个进程只有一份世界状态，所以服务端同一时刻只能跑一张图）。
- **暂停 / 离开**：按 **Esc** 打开菜单——「继续战斗」回到战场（暂停时房主这台电脑上的整局都会停住，
  别人看到画面停住并收到提示），「邀请朋友」仍可打开配对工具（新会话须等下一大厅），「离开对局」回到主菜单（房主的房间会一起关掉，
  别人会收到明确提示）。Esc 永远不会把人卡在对局里出不来。
- 聊天、计分板、击杀提示、击杀播报都与局域网一致。房主关掉页面后，其他人会看到
  「与房主失去联系」，回主菜单重新加入别的房间即可。
- **自建中转仍然可选**：给网址加 `?relay=wss://你的中转:端口/mqtt`（例如内网的 mosquitto / EMQX /
  HiveMQ），或 `localStorage.setItem('tf.relay.broker', 'wss://…')` 固定下来。没有任何外部中转
  时页面也照常工作，因为默认根本不用它。
- **出问题时先看诊断页**：`/debug.html` 一次列出三个 `/api/*` 端点返回了什么、浏览器的能力
  （WebRTC / BroadcastChannel / WebAssembly…），还能做一次**本机点对点自测**
  （两条 WebRTC 连接互相发一句话）并复制成一份报告。此页独立运行，只加载 `debug.js`，
  不加载 `main.js`，也无法读取其他标签页的游戏状态。「此诊断页不启动 main.js（正常）」
  是说明而非游戏装载错误。若要排查游戏启动，请返回 `index.html`，查看**游戏页面**的控制台。
  本机自测通过不代表游戏已启动，也不保证不同设备/网络之间能连接。详见[诊断状态与回归检查](docs/diagnostics.md)。
  自建服务端（下一节）仍然是想要固定大厅、共享角色库时更好的选择。

### 诊断与游戏启动排查

`/debug.html` 以前显示的红色 **“没有加载（main.js 没跑起来）”** 属于误报。
诊断页有意只加载 `debug.js`，不加载游戏的 `main.js`。每个页面有独立的 `window`，从游戏跳转到诊断页后，
不会保留 `window.__trench`，也不能读取另一个标签页的游戏状态。修正后的提示是
**“此诊断页不启动 main.js（正常）”**，既不表示游戏失败，也不声称游戏已经成功启动。

| 看到的情况 | 含义与下一步 |
| --- | --- |
| 诊断页显示正常/未启动游戏 | 正常现象。点击**「回到游戏」**打开 `index.html`；反复刷新诊断页不会启动游戏。 |
| 本机 P2P 自测通过 | 同一浏览器内的两个真实 WebRTC 连接通过游戏的邀请码/回答码流程互发消息；不代表游戏启动成功，也不保证不同设备或网络能够连接。 |
| API 或 P2P 检查失败 | 该项检查确实失败，错误仍会显示。请复制报告，保留接口状态和日志。 |
| 游戏本身卡在装载画面 | 在 **`index.html` 游戏页面**打开开发者工具，而不是在诊断页。检查 Console 与 Network 中最先出现的错误、失败的模块/数据请求、HTTP 状态或错误 MIME 类型；反馈时附资源网址。 |
| 开发者工具提示 CSS `@import` 被忽略 | 这是独立的样式问题，不等于 JavaScript 加载失败。展开 **Affected resources / 受影响的资源**，查看具体样式表网址。当前项目样式表/HTML 没有 `@import`，专项检查也未复现此警告；不声称已修复来源不明的样式表。 |

无游戏实例时，**「复制报告」**会包含 `multiplayer.scope: "current-document-only"` 和
`multiplayer.runtimeStatus: "not-applicable-on-diagnostics-page"`。
此时引擎为 null、通道为空表示**未观测到**，并非游戏故障。若开发者在同一页面提供了游戏实例句柄，
状态为 `app-handle-present`，也不等于完整启动成功。

专项回归命令如下；需使用外置的浏览器测试依赖，游戏运行/部署不新增 npm、后端或构建步骤：

```sh
node --check public/js/debug.js
node tools/test-diagnostics.mjs
node tools/test-landing.mjs
```

诊断测试覆盖中英文、重新探测、复制报告的状态范围、真实本机双向 RTC、1280/390/320px 布局、
HTTP 503 错误保留，以及实际点击返回链接后加载 `main.js` 并进入游戏主菜单。
这不代表真实手机/跨 NAT 网络认证，也不是完整玩法测试。
运行 `DIAGNOSTICS_SCREENSHOTS=1 node tools/test-diagnostics.mjs` 可将检查截图保存到 `/tmp`。
实现细节、测试依赖与验证边界见[诊断说明](docs/diagnostics.md)。

### 在受限的浏览器环境里运行

游戏本体不需要任何插件，但有两种浏览器环境会限制网页，已经都处理好了：

- **鼠标视角只使用原生指针锁定**：点击游戏画面捕获鼠标，移动鼠标转动视角；**Esc 释放鼠标并打开
  暂停菜单**。点击继续时重新请求原生锁定。**没有光标转向、边缘转向或拖拽瞄准降级模式**。
  锁定失败后可以再次点击重试，临时拒绝不会永久禁用原生锁定。失焦、Esc、离开对局会清空输入并取消蓄力。
- **iframe / 预览页面**：只要父页面允许，就可以使用原生指针锁定。如果你控制嵌入页面，
  请在 sandbox 权限中加入 `allow-pointer-lock`，例如：

  ```html
  <iframe src="https://your-game.vercel.app/"
          sandbox="allow-scripts allow-same-origin allow-pointer-lock"></iframe>
  ```

  如果预览面板的父页面禁止锁定，游戏会保持鼠标自由，提示重试或**在新标签页打开**，而不是更换控制方式。
  子页面无法覆盖父级 sandbox 限制；请使用支持 Pointer Lock API 的浏览器，在独立标签页中打开游戏。
  不支持此 API 的浏览器无法实现原生鼠标捕获。
- **仅部署 Vercel、不能建立 WebSocket 的环境**：使用上述浏览器房主引擎 + `BroadcastChannel` /
  WebRTC 联机，**不需要 `/ws` 或 `/api/poll`**。Vercel Functions 中没有持续运行的游戏服务器或
  共享房间状态。禁用 WebSocket 不等于禁用 WebRTC，但禁用 WebRTC/UDP 仍可能阻止跨电脑联机。
- **另外部署 Python 服务端、但代理不允许 WebSocket 的环境**：只有这种部署支持自动回退到
  `POST /api/poll` 长轮询。它**不是仅部署 Vercel 时的备用通道**。
- 另外：主菜单的「服务器地址」填错或过期时，会自动回退到**当前页面的服务器**并在菜单下方说明；
  浏览器禁用本地存储、禁用 WebGL 的情况也会在加载页给出明确提示，而不是一直卡在载入画面。

### 出生保护、后坐力与地图安全

- 首次出生、重生和新回合均获得**最多 5 秒权威保护**，玩家和机器人适用同一规则；
  移动、成功开火或投掷手榴弹会立即结束**该玩家自己的**护盾，未行动的对手仍保留自己的保护。

  蓝色护盾球和血量栏倒计时显示剩余时间。

  成功发射侦察兵进攻信号弹则会取消。房主同时检查移动意图和真实接受位移，容忍极小坐标舍入噪声，

### 楼梯可靠性与头顶空间

**已修复的间歇问题：** 较晚到达的移动数据包一次跨过较长楼梯时，旧碰撞扫描始终沿用包起点的脚底高度，
会把连续坡面误当成超过 0.65 米的大台阶；水平位置被提前拦住，权威端却可能仍接受更高的垂直位置，表现为
上不去、停顿或位置拉扯。另一处问题是叠层楼梯下起跳时使用斜板包围盒的平底，而不是真正倾斜的底面，可能漏掉撞头。

**现在如何移动：**

1. 浏览器 `World.resolveMove` 与 Python/Pyodide 的 `combat.resolve_move` 按不超过 **0.175 米**的间隔
   扫描整条水平路径（角色半径 0.35 米的一半），每个成功子步都更新实际支撑高度。
2. **0.65 米台阶上限逐子步生效**，而不是限制整包沿连续坡面的累计上升。最后使用扫描得到的支撑高度，
   不再用过期脚底高度重新查询。原有移动速度限制和实体墙碰撞仍然有效，不能借此爬上高墙。
3. 每次抬高脚底都会按当前站立/蹲下身高检查完整身体空间；低顶下站不下的台阶会被拒绝，只有实际蹲下能容纳身体时才能通过。
4. 下坡贴合坡面；大于一步的落差仍按重力下落，空中扫描保留真实脚底高度而不累计贴地抬升，不会把悬崖当成普通下台阶。
5. `World.ceilingAt` 与 `combat.ceiling_at` 使用当前位置的**坡面高度减斜板厚度**作为底面，客户端和权威端
   都在底面前停止上升。旧式实心楔形坡道仍使用其平底，普通楼板/天花板保持原来的平面边界。

**几何没有重做：** 城市层高仍为 3 米，站立角色 1.70 米；全部 **163 段楼梯**保持 22 厘米厚连续斜板，
叠层斜板之间保留 2.78 米净距。踏步只是视觉模型，不使用一条条木板碰撞；楼上有真实的楼梯井开口。
本次是运行时代码修复，不需要重新生成地图、安装物理引擎、执行 npm 或前端构建。

### 稳定鼠标输入与不同水平的 AI

- 原生指针锁定的移动包按帧合并，采用约 8 毫秒的短时滤波；拒绝非有限数值、过大的跳变包，
  以及刚锁定/调整窗口时的大幅回中包。每帧转角与积压输入均有上限，避免卡帧后突然旋转。
  普通输入和正常的多包快速甩枪保留总转角；极端卡顿产生的过量积压会主动截断。
  镜头与开火共用**同一个滤波后瞄准方向**，开镜缩放精度保持不变。
- 主菜单和 Esc 暂停菜单新增 **25–200% 鼠标灵敏度**，两个滑杆同步并保存在本机档案里；
  浏览器允许本地存储时，刷新后仍有效。锁定切换、Esc、失焦、隐藏标签页、窗口变化与复活
  都会清除待处理输入。仍然只使用原生指针锁定，绝不改为自由光标转向。
- **混合难度**沿用每队**新兵 / 普通 / 老兵**轮换，Tab 战绩表显示对应标签。
  也可统一选择简单/普通/困难，以及新增的**专家 · 精英**（反应 120–240 毫秒）。
  新兵反应 550–1000 毫秒，转身较慢、水平/垂直瞄准误差更大、点射间隔更长；普通兵反应
  300–600 毫秒；老兵反应 150–300 毫秒，跟枪更紧、停顿更短。这是发现目标后的反应延迟，
  不是保证的首次开枪时间。每队按「新兵、普通、老兵、新兵、普通、普通」循环分配，
  小队取该序列前几位，所以多数 AI 并非高手；复活后保留水平。生命、伤害、视野/烟雾、
  队友射线保护、掩体、职业技能和权威武器规则不变；低水平也照常寻路、占点，不会凭空看穿墙壁。

`node tools/test-mouse.mjs` 检查跳变/非法输入、锁定首包、24/60/144 Hz 精度、快速甩枪与卡帧积压。

和战绩表标签，以及既有瞄准/开火/联机功能。`python tools/test-ai.py` 共 36 项回归，覆盖水平、

### 单人和多人的 AI 难度

在主页面先选择**「单人 AI 数量」**或**「多人 AI 数量（房主）」**，再选**「AI 难度」**。
单人保留各地图的数量偏好（旧城默认 15）；多人默认 **0**，除非房主主动添加，否则仍为纯真人房间。
AI 数量和难度独立设置。

| 难度 | 水平 / 发现目标后的反应延迟 | 战术特点 |
| --- | --- | --- |
| 混合（均衡） | 原有每队新兵/普通/老兵轮换 | 多数是普通士兵，不混入精英 |
| 简单 | 新兵 / 550–1000 毫秒 | 瞄准较松，停顿与决策失误更多 |
| 普通 | 普通兵 / 300–600 毫秒 | 跟枪、掩体和战术选择较均衡 |
| 困难 | 老兵 / 150–300 毫秒 | 协同更可靠，被多个已见敌人压制时更会找掩体 |
| 专家 | 精英 / 120–240 毫秒 | 更稳定的跟枪和决策，但仍非瞬间反应或完美瞄准 |

- 机器人会根据生命、武器理想距离、压制、已见威胁与附近队友，为**推进、坚守、横移、侧翼、撤退**评分。
  支援武器或已有队友侧翼时，更倾向留人架枪，减少全队重复绕同一路线；难度越高，决策噪声越低。
- 高水平会更早找掩体、较久记住最后看见的位置，但不会读取隐藏目标的实时位置。
  主武器弹匣/备用弹全部耗尽时，可按正常切枪延迟与独立弹药规则改用有弹手枪。
  各水平生命、伤害、遮挡/烟雾/闪光和权威武器规则相同；原有单人平衡保护不变，客人加入不会让多人房获得单人优惠。
- 多人 AI 与难度仅由**房主**设置。客人只读查看，加入消息或直接命令不能篡改；房主修改 AI 后会撤销准备，
  需要客人重新准备，再由房主统一开始。已审批加入/重进不会清空 AI，复活也保留水平。
- 最多 16 个机器人、总人数最多 32；真人加入需要位置时减少 AI，离开后补回目标数量，最后一位真人离开则清空 AI。
- 中英文界面、本机记忆和 `public/shared/bots.json` 统一调参同时适用于 Python 与浏览器/Pyodide 房主；
  不新增构建步骤、必需后端、在线 AI 服务或生产环境 npm 依赖。

这是手写效用评分/协同战术，**不是机器学习，也不是完整的小队规划器**。
在线研究来源、参数、权限与验证边界见[AI 难度与智能行为](docs/bot-difficulty.md)。专项检查：

### 更智能的 AI 与镜头碰撞

- **减少固定套路：**每条命分别生成稳定度和进攻倾向，使用运行时随机，而非所有对局重复同一固定随机种子。
  推进、侧翼、横移、后撤决策会承诺执行 1.3–3.1 秒；短暂停住观察持续 350–850 毫秒。
  侧翼目标先检查边界、地板高度和实体碰撞，再走已有的有界寻路；不安全则退回横移。
  低血量/换弹找掩体仍优先，停住时不再因队友分离转向而莫名漂移。
- **跟枪会犯错：**根据各水平的分次目视观测估算速度，不读取目标的实时/隐藏速度。
  预测最多前推 180 毫秒、每轴最多 1.2 米，突然变向可骗过机器人；瞄准误差平滑变化，
  远距离不会反而收缩成“激光枪”，受压制时误差更大。
- 每次准备新一轮点射，新兵/普通/老兵/精英分别有 **22% / 13% / 7% / 4%** 概率犹豫 **180–550 毫秒**。
  这是延误开火机会，不是命中率；配合跟枪误判、偶尔冒进和个体差异，让机器人确实犯错，
  不靠增加血量、伤害、弹药或穿墙特权来变强。
- 据点选择考虑已分配/已在附近的队友和公开争夺状态，承诺保持 1.8–3.5 秒，减少所有 AI 挤同一点。
  城市楼层观察点随机选择，横移方向也可保持原方向，不再机械地左右轮换。
- 机器人通过视野、实体遮挡与烟雾判断敌人，只会短暂搜索最后看见的位置，不会隔墙追踪隐藏玩家。
  目标切换迟滞、反应时间、按枪械区分的交战距离和短点射使战斗更自然。
- 低血量或换弹时寻找实际遮挡的掩体，安全时提前补充弹匣，避免朝挡在射线上的队友开火，并按
  附近队伍需要放置医疗/弹药箱。调查和寻找掩体采用有上限且缓存的 A*，移动仍结合地图流场、
  连续碰撞采样与脱困逻辑。弹药、射速、伤害和技能仍走玩家同一权威路径；既有的单人模式机器人
  对人类子弹命中 50% 概率免伤保持不变，与新增跟枪误判和犹豫独立，不需要机器学习或外部服务。
- 第一/第三人称镜头按近裁剪面大小进行体积扫掠，处理墙壁、坡道、地面与天花板；第三人称遇墙
  收近，第一人称修正近裁剪面穿墙（包括宽屏边角）。跳跃也会被天花板阻挡。第三人称镜头收得
  太近时隐藏本地角色身体，不隐藏其他玩家。镜头修正不移动角色身体或权威射击射线。
- 30 把枪的枪口焰即使低帧率也至少显示一帧；本地和远端枪口焰跟随当前枪口，弹壳保留每把枪的
  尺寸，烟气各自淡出，远端枪声使用对应枪械采样。权威开火序号避免短开火标记丢失及重复/乱序
  快照造成的重复特效；旧房主仍使用按射速限制的兼容逻辑，特效对象池仍有数量上限。

### 新手教程

现在共有 **11 步**：移动 → 原生鼠标视角 → 开火 → 瞄准 → 换弹 → 蹲跳 → Q 技能 →
**B 切换与 G 蓄力投掷 → 实际占领据点** → 战绩 / 视角 → 联机房号。
练习始终在私密的索姆河据点局进行，没有机器人，也不会误入此前填过房号的多人房间。
Q / G 步骤要等权威引擎确认技能生效；只切换、取消投掷或因冷却被拒绝都不算完成。
据点步骤只认权威状态中的实际所有权。游戏中面板只展开当前一步，最后按 Enter 完成并回主菜单；
也可以按 Esc 后使用面板按钮。完成状态保存在本机，可从主菜单重新打开。

### 据点控制规则

单人或创建多人房间前，在 **游戏规则 → 据点控制** 中选择；死斗仍保留为默认规则。
加入者遵循房主规则，不能通过本地选择或伪造占领消息改变正在进行的比赛。
索姆河与意大利均有可从双方出生区到达的 **A / B / C**，地图旗帜和顶部卡片显示所有权、
占领进度、争夺状态、方向、距离与全点倒计时。

- 在 **5 米**圈内、相近楼层且能直视旗点时才有效；单人 **5 秒**占领，两人协同更快，最多按两人加速。
- 双方同时在圈内会阻止推进；敌方据点须先中立化，再占领。无人继续时部分进度回退，已占领点保留所有权。
- **全队拥有全部三点并连续守住 15 秒获胜**。敌人争夺或开始中立化任一据点就会清空全点倒计时。
- 击杀仍计入个人战绩，但不能赢下据点模式。8 分钟结束时拥有更多点的队伍获胜，同数平局。
  新一轮会重置旗点并同步重生位置；单人 AI 会主动寻路占点、争夺并应对防守压力。
- 中途加入同步规则和现有旗点。继续使用 Vercel 静态资源与浏览器权威引擎，不增加必需的外部服务。

### 本机存档（不需要任何 SQL 服务器）

### 自定义角色（设置模式）

1. 进入「设置模式」，选择带蒙皮的 `.glb` / `.gltf`（不支持 Draco / meshopt / KTX2，也不支持
   依赖外部 `.bin` 与贴图的 `.gltf`）。
2. 骨骼会自动按名字匹配到 13 个游戏关节（髋 / 脊柱 / 头 / 双肩 / 双肘 / 双腕 / 双膝 / 双踝），
   可以逐个手改；肩、肘、手不参与程序化动画，用偏移滑杆摆出持枪姿势。
3. 「缩放」「朝向」用于微调，归一化后角色会按 1.70 m 站高对齐游戏命中盒。
4. 「上传共享」会把模型与映射发给服务器（`POST /api/character`，单个文件上限 24MB），

### 手榴弹与投掷物理

所有兵种都有独立于 Q 技能的 **2 发共享手榴弹槽**。按 **B** 选类型，按住 **G** 最多蓄力
900 毫秒，松开投掷；抬头抛得更远，低头可近距离轻抛。金色轨迹会预览重力和墙面、斜坡、
地面的碰撞反弹。投掷继承部分经过权威校验的移动速度，反弹会损失能量，低速后停稳。
引信从**松手**开始计时，不会在蓄力时炸在手中。Esc、失焦、打开聊天、死亡或失去原生鼠标
锁定都会取消尚未松手的投掷，不消耗次数；用完第 2 发后 24 秒补满，重生也会补满。

| 类型 | 引爆与效果 |
| --- | --- |
| **破片** | 2.6 秒引信，短促爆闪、金属碎片、火星、尘烟与分层爆炸声；7 米内最高 120 伤害，随距离衰减。 |
| **燃烧** | 碰撞引燃，3 秒保险引信；燃料落到碰撞点下方地面，火焰与余烬持续 7 秒，4 米内每秒 28 伤害。 |
| **烟雾** | 1.8 秒引信；小型点火效果后生成原有的 14 秒、13 米遮蔽烟团。 |
| **毒气** | 1.8 秒引信；黄褐色烟雾持续 12 秒，半径 6.5 米，未防护的敌人/投掷者每秒受 18 伤害。按 **M** 或手机「防毒面具」，密封 0.75 秒后保护生效。 |
| **闪光** | 1.6 秒引信；14 米内未被掩体挡住的玩家先看到**完全不透明的全白屏幕**，随后平滑恢复，不频闪。距离和朝向影响恢复时间，AI 也会暂时失去视野。 |

**`smoke_granade.glb` 用于烟雾**、**`flashbang_grenade.glb` 用于闪光**、
**`gas_grenade.glb` 用于毒气**。毒气原文件是两个弹体的展示场景，实际只投掷其中直立的一颗。

## 玩法规则

- 目标：先达到 **75 击杀**的一方获胜，或 **8 分钟**时间到时比分高的一方获胜。
- 阵亡后 3 秒可重新部署，能免费选择兵种、主武器与手枪副武器，再按「重新部署」确认。
  真人玩家确认前不会被自动复活打断选择；机器人仍会自动复活。更换兵种、主武器或界面语言不会清除已选手枪。
- **呼吸回血**：连续 **8 秒**没有被子弹或爆炸命中，就会开始自动回血，并在 **8 秒内回满**
  （上限为自身最大生命值）。对该玩家造成任意伤害都会重置这个 8 秒计时；医疗包治疗区
  的回血与呼吸回血可以叠加。真人玩家与 AI 机器人都适用同一条规则。
- 视角：默认第一人称，按 `V` 可切到第三人称观察自己的角色模型（第一人称下看到的是
  与角色模型同源的双臂与武器；第三人称只移动相机，瞄准射线与命中判定完全不变）。
- 本作没有小地图：唯一能主动暴露敌人位置的手段是侦察兵的信号弹（被标记的敌人全队可见）。

## 部署

服务端是**单进程、单端口**的 aiohttp 应用，没有数据库、没有构建步骤，因此部署就是「装一个依赖、
跑一个命令」。仓库里已经备好三种落地方式：

**Docker（任何平台都能用）**

```bash
docker build -t trench-front .
docker run -p 8080:8080 trench-front
```

镜像基于 `python:3.12-slim`，只装 aiohttp，以非 root 用户运行，自带基于 `/api/health` 的
`HEALTHCHECK`。`PORT` 环境变量被显式读取（见下）。

**Render**：仓库根目录的 `render.yaml` 就是一份可直接用的 Blueprint——连接仓库、选择
Blueprint 即可（免费档会休眠，唤醒后第一次进入要等几秒）。健康检查路径 `/api/health`。
**这是最省事的「一键就能玩」方式**：它同时托管前端和游戏服务端。

**Heroku / Railway / Koyeb**：`Procfile` 已就位（`web: python server/server.py`），它们注入的
`PORT` 会被自动采用。

**Vercel（不需要任何后端，推荐）**

Vercel 的函数是「请求进、响应出」：没有 WebSocket，也没有常驻的 30 Hz 对局循环，所以游戏服务端跑不了
Vercel。但**对局本身也不需要服务端**——`public/engine/*.py` 就是服务端那同一份代码，页面用
**Pyodide**（WebAssembly 版 Python，随仓库一起部署在 `public/vendor/pyodide/`）把它拉进浏览器里跑，
`public/js/local.js` 负责驱动它。所以纯静态托管也是**能直接开打**的：单机 + 机器人，和自建服务端
玩起来是同一套规则、同一套弹道、同一套机器人 AI。

1. 在 Vercel 里 Import 这个仓库，Framework Preset 选 **Other**，Build Command / Output Directory
   都留空。
2. **把 Root Directory 设成 `public`**（Settings → Build and Deployment → Root Directory）。
   项目配置就在 `public/vercel.json`：`/api/*` 的三条接口重写到静态垫片文件，`/vendor/pyodide/*`
   带长缓存与正确的 MIME。仓库根目录那份 `vercel.json` 是给「Root Directory 留空」的老用法准备的，
   两套都留着，用的是哪套由 Root Directory 决定。
3. Deploy。打开网址 → 主菜单 → 单机/多人都可点「部署」：
   - 单机：浏览器内嵌引擎开局（浏览器里会显示「静态托管：对局由浏览器内嵌引擎运行」）。
   - 多人：**同样不需要服务器**——「创建房间」时这一局就在你的浏览器里跑，把房号 / 邀请链接
     发给朋友（同一浏览器多开标签页即可用房号进；不同电脑用「邀请朋友」的两个码直连），
     见上面「网页版联机」一节，多个房间可以同时跑不同地图。
     只有想要固定大厅、共享角色库（上传 GLB 给别人用）时，才需要下面 Render / Docker 的真服务端；
     那时在菜单的**「服务器地址」**里填它，或给网址加 `?server=your-app.onrender.com`。

静态托管上的接口由 `public/api/*.json` 垫片回答（`/api/health` 返回 `{"ok":true,"engine":"local"}`，
客户端据此知道「这个源没有服务端，改用页内引擎」）：菜单能开、内置角色都在，房间列表由页面从
中继上收集（垫片里是空的），角色上传需要真服务端（垫片会说明）。首次进入要下载约 12 MB 的 Python 运行时（之后走缓存），
只是第一次比平时慢几秒。

两个坑：**https 页面只能连 https 后端**（浏览器禁止 https 页面开 `ws://`），所以后端也要 https；
GitHub Pages 那种「放在子路径下」的托管需要注意——页面资源是绝对路径 `/js/...`，只在域名根目录下成立。

平台相关的行为：

- `PORT`：有该环境变量时**只用这一个端口**，不会再 8080→8081 顺延（顺延会让平台的端口映射 502）；
  本地没有 `PORT` 时仍然是 8080 起顺延 20 个端口。也可以用 `python server/server.py --port 9000`。
- 绑定 `0.0.0.0`（可用 `TRENCH_HOST` 覆盖），因为容器里绑 127.0.0.1 外面就进不来。
- HTTPS 页面自动使用 `wss://`（`main.js` 按 `location.protocol` 选择），WebSocket 被代理挡住时
  自动降级为 HTTP 长轮询，所以放在只允许普通 HTTP 的网关后面也能玩。
- **只能单实例**：房间、比分、地图都在内存里，而且服务器同一时刻只跑一张地图（`combat.py` 只有
  一份世界状态），所以不要开多副本 / 自动扩缩容，也不要开 sticky session——一个进程就是全部。
  （想要「一张地图同时被多个房间用」，走上面「网页版联机」那条路：房间在玩家浏览器里跑，
  每个房主各自一份世界状态。）
- 上传的共享角色模型写在 `public/shared/characters/`，容器重启即消失；要长期保存请挂载该目录。
- 静态资源分两档：模型/音效/`vendor`（合计 40 MB 左右）带 `Cache-Control: max-age=600` +
  ETag，第二次进图只发 304；`js`/`css`/`html`/`json` 仍然是 `no-store`，改完刷新即生效。
- 静态托管（Vercel）与自建服务端的区别只有一处：`/api/health` 的答复里带不带 `"engine":"local"`。
  带 → 页面用内嵌引擎（`public/js/local.js` + Pyodide），多人走玩家自己主持的房间（`public/js/relay.js`：
  同浏览器标签页用 BroadcastChannel，跨电脑用 `public/js/p2p.js` 的点对点直连，不需要任何服务）；
  不带 → 一切照旧走网络。
- 前后端可以分开部署：`public/js/api.js` 记住「`/api/...` 该问谁」。玩家在菜单里填了服务器
  地址（或网址带 `?server=`）之后，房间列表、共享角色库、角色上传都跟着那台服务器走；只有
  模型 / 音效 / `/shared/*.json` 还是从打开页面的地方加载。

## 技术要点

- **单一数据源**：所有数值都在 `public/shared/*.json`，服务端与客户端读同一份，不可能漂移。
  `python public/engine/combat.py` 可随时校验这份数据是否自洽。
- **一份服务端，两个宿主**：`room.py` / `game.py` / `combat.py` / `bots.py` 里没有任何 socket 代码，
  aiohttp 宿主（`server/server.py`）与页内宿主（`engine/host.py`，跑在 Pyodide 里）驱动的是同一个
  `Room`。所以「静态托管上的单机对局」不是另写一套简化版：弹道、伤害衰减、部位倍率、机器人 AI、
  地图投票、计分全部是同一份实现，网页上的表现和自建服完全一致。
- **出生点必有出路**：出生点在地图数据里本来就已经验证过「平地 + 头顶无遮挡」，但地图完全可能
  把一个碉堡摆在出生点正前方两米——出生即面壁，按住 W 寸步难行。现在 `random_spawn` 会把
  「面前 5 米可走」当作首选条件，被迫用的墙角出生点也会自动转向开阔方向，因此三个出生点仍然轮流使用，
  只是不再有人对着沙袋出生。
- **服务端权威**：命中判定、伤害、弹药、射速、技能冷却、计分全部由服务器决定，
  客户端只上报「我在哪」和「我朝哪开枪」，说别的都不作数。
- **客户端权威移动 + 服务端钳制**：移动手感在本机即时响应，服务器对位移做距离与边界校验后滑墙修正。
- **延迟补偿**：服务端为每个玩家维护一条 1 秒的位置环形缓冲（30Hz 采样一条，共
  `historyMs: 1000` 毫秒）。开火时把**所有目标**回滚到
  `ping/2 + interpDelayMs(120ms)` 之前的位置再做射线判定——也就是 shooter 客户端
  当时实际画在屏幕上的那个位置，所以「明明瞄准了却没伤害」不会再发生。
  细节：回滚窗口上限 `lagCompMaxMs: 220`；客户端自报的 RTT 在服务端硬钳到 240ms
  （虚报延迟只会让自己更容易被打中）；机器人不参与回滚（它们没有网络延迟）；
  复活与阵亡时会重置该玩家的缓冲，避免回滚跨越死亡打到旧位置。
- **外部骨骼角色**：上传的模型不可能认识游戏的关节命名，所以 `rig.js` 不做骨骼重定向，而是
  「进入时捕获 rest quaternion，每帧 `rest × delta`」——这是唯一跨模型都成立的写法。腿、脊柱、头
  由程序化步态驱动，肩 / 肘 / 腕不参与动画，留给用户的偏移滑杆摆持枪姿势。缩放靠 `Box3` 实测高度
  归一到 1.70 m 站高，与命中盒对齐。项目里没有 SkeletonUtils，蒙皮克隆自己实现（`clone(true)` 后
  按遍历顺序重绑 `Skeleton` + `boneInverses`）。模型的 id 随玩家状态一起下发（`state.ps[].sk`），
  远端玩家按它切换模型，模板懒加载完成后自动换装。
- **光照 / 材质健壮性**：地图的灯光、雾、天空色先过一遍 `lighting.js` 校验（缺项补默认值、
  颜色非法就丢弃、`fogFar > fogNear` 强制成立），所以地图文件写坏也不会黑屏；同时生成一张
  程序化天空的 PMREM 环境贴图挂到 `scene.environment`，供金属度较高的 glTF 枪械反射——
  导入的 PBR 模型金属度 1.0 而没有环境贴图时会渲染成全黑，这就是修掉的「黑模型」问题；
  完全没有贴图的金属材质会被压到 `metalness ≤ 0.6`。unlit 资源（`KHR_materials_unlit`）保持原样。
- **开火表现全部池化**：枪口焰、硝烟、弹壳都是预先建好的对象池（8 / 18 / 16 个），开火时只
  重新摆放，不分配、不销毁——900 发/分的自动武器也不会让 GC 抖动。枪口光用的是**常驻场景**的
  两盏 `PointLight`（平时强度 0）：三盏灯忽隐忽现会让 three.js 把整个世界重新编译一遍着色器，
  而常驻灯只是多一点点逐像素开销。后坐现在改变**真实瞄准方向**，瞄准时减轻；渲染镜头与后续
  子弹射线保持对齐，不再只有画面抖动。枪身仍有独立的平滑回位动作。
- **二次元渲染**：4 级阶梯渐变的 `MeshToonMaterial` + 倒壳描边 + 头发高光带；
  不开实时阴影，用脚下的深色圆片当假阴影；面部与立绘全部由 Canvas 程序化绘制，不依赖任何图片资源。

## 击杀反馈与阵亡动画

确认击杀后显示金色动态命中标记、被击杀者名字卡片、独立爆头提示与短时间连续击杀计数。
只响应权威击杀事件，不把预测命中当成击杀；不会强制转动击杀者镜头，也不会打断瞄准。

四套导入角色和程序化角色现在都会先受击、屈膝失去支撑、倒地并收势；能取得攻击者位置时，
按远离攻击者的方向倒下。尸体短暂保留，最多 4.2 秒，复活时立即恢复。自己阵亡后第一人称手臂立即隐藏，
镜头平滑退到经过墙体碰撞检查的倒地视角，约一秒后出现原有兵种／主武器／手枪重新部署面板。
复活倒计时从阵亡即开始，不会因为动画重新计时；镜头与界面按真实时间推进，低帧率不会延长等待。
系统开启「减少动态效果」时取消镜头滚转与动画拉远，简化击杀提示的运动。

这是有界的**关键帧视觉表现，不是物理布娃娃**，不改变伤害、弹道、移动、命中体积、分数、出生护盾或联机协议。
实现细节、限制与测试命令见[战斗动画说明](docs/combat-animation.md)。

## 蹲姿修正与多人联机严格检查

蹲下不再是「大腿向后、小幅弯腿」的近站立姿势：四套导入角色与程序化角色共用平滑的
髋／膝／踝下蹲曲线，骨盆按脚底支撑真正下降，蹲走使用短步幅，站立／跑步／蹲下切换不再突跳。
躯干前倾时武器反向补偿俯仰，维持平举和原有手部 IK；没有修改权威碰撞体、眼高、速度或命中规则。
深蹲回归还发现了阵亡地面探测使用过期蒙皮矩阵的问题，现已先刷新 SkinnedMesh 再采样，
避免从深蹲开始倒地时脚部穿过支撑平面。模型的帽子、头发等装饰仍不等于游戏碰撞体。

本次修复了实际复现的联机问题：

1. **部署时误关掉已经配对的 RTC。** 原先会优先尝试保存的可选后端地址，关闭现有直连后再回退到
   没有配对的新通道。现在明确创建／已完成配对的房间优先，并复用现有通道；保存地址格式错误也不会
   阻止已配对房间部署。没有配对、明确使用后端的玩家仍保留原来的后端连接流程。
2. **房主模拟依赖绘制帧。** 改为独立定时推进，引入中继数据到达时也可推进权威模拟，
   限制停顿后的追赶步数，关闭时清理定时器；即使停用房主 requestAnimationFrame，三张地图仍可联机。
   这不等于能绕过操作系统完整挂起浏览器：房主必须保留页面，尽量避免设备休眠。
3. **暂停与房间存活不同步。** 客户端暂停菜单期间继续发送传输心跳，避免仅因停止游戏输入就丢失席位；
   房主明确广播暂停／恢复，暂停期间客户端不能移动或开火，权威端也拒绝游戏指令。
   聊天、普通回复与心跳都保留暂停状态，不能因为发了聊天消息就误恢复客户端。

**仍是纯静态 Vercel 部署，不增加构建步骤、必需后端或消息代理。**
八位房号只适用于同源、同一浏览器存储分区的标签页。不同浏览器／设备必须先完成「邀请朋友」的
邀请码与回答码交换，不能只发房号就期待跨设备直连。可选 STUN 只能辅助发现网络地址，不是 TURN
中继；严格 NAT／防火墙仍可能无法建立直连，不能保证任意互联网环境都可连接。

`node tools/test-multiplayer.mjs` 已完整通过：分离浏览器上下文，明确禁用 BroadcastChannel、
WebSocket 与外部请求，走真实菜单创建／邀请／回答／配对／部署；验证键盘蹲走同步、暂停／心跳、
双方伤害击杀、倒地、重新部署、手枪选择、弹药／换弹及离开清理；离开后再通过菜单配对并重新加入，
确认房主席位与当前生命不被重置。Somme、Italy、Procedural City
另逐图验证提前加入、房主地图与规则覆盖、多人无机器人、私有弹药、双向聊天、护盾自然到期与房主退出，
并刻意停止房主绘制来验证模拟独立性。完整击杀对战在 Somme 进行，不把逐图传输测试夸大成所有角落的
战斗覆盖；这些是本地真实 RTC 测试，不是两条物理网络或线上 Vercel 连通性认证。

新增蹲姿回归覆盖五类角色、20／60／144Hz、静止与移动、站蹲过渡；保留全部 30 把枪的握持、换弹、
150 组 Gun Lab 组合及深蹲阵亡检查。实现原因、测试命令与限制详见
[蹲姿与联机检查说明](docs/crouch-and-multiplayer-checks.md)。

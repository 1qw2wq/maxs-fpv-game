# 堑壕前线 Trench Front

一战主题的多人联机 FPS 团队死斗网页小游戏。四个兵种（突击兵 / 医疗兵 / 支援兵 / 侦察兵），
每个兵种 3 把武器，全部可操纵角色为**二次元风格美少女**（半写实比例，约 5.7 头身）。

无构建步骤：前端是原生 ES Module + import map，后端是单个 Python 进程同时提供静态文件与 WebSocket。
**也可以完全没有后端**：纯静态托管（Vercel / 任何静态服务器）时，浏览器的内嵌 Python（Pyodide）
会跑起同一份服务端代码，单机 + 机器人对局照常进行——见「部署 → Vercel」。

> English documentation: **[README.en.md](README.en.md)**.

## 界面语言（中文 / English）

整个界面都是双语的，随时可切换：

| 位置 | 作用 |
| --- | --- |
| 主菜单右上角的 **EN / 中文 按钮** | 一键切换整个界面，立即生效 |
| **「设置模式」里的「界面语言」** | 同样的切换，旁边就是角色模型工具 |
| 网址加 `?lang=en` / `?lang=zh` | 本次访问强制使用该语言 |
| 什么都不做 | 第一次访问跟随浏览器：中文浏览器用中文，其它用英文 |

选择会记在 `localStorage` 的 `tf.lang` 里，下次打开继续用。武器、兵种、队伍、地图的名字与说明
也一起翻译（数据文件里 `name` / `nameEn`、`desc` / `descEn` 成对存在），
兵种与武器卡片**第二行固定显示另一种语言的写法**，两种拼写始终同屏可见。
切回中文后与中文用户看到的内容逐字一致。

## 运行

需要 **Python 3.10+** 与 **aiohttp**（不需要 Node.js，也没有任何打包步骤）。

**推荐：直接双击项目根目录里的 `启动服务器.bat`。** 它会自己装好 aiohttp（首次）、启动服务器、
**并自动用默认浏览器打开游戏页面**，不需要手输网址。它同时把本机地址与局域网地址打印在一个独立的
命令行窗口里。这个窗口和编辑器（TRAE / VS Code）完全无关，
**关掉编辑器也不会让服务器停止**——只有关闭那个命令行窗口、或按 `Ctrl+C` 才会停。
想长期开着让同学联机，就双击它，不要依赖编辑器里的「运行」。
（端口被占用自动顺延时，打开的也是顺延后的正确地址，因为网址由服务器自己给出。）

手动运行（等价，`--open` 可选，加了就自动开浏览器）：

```bash
pip install aiohttp
python server/server.py --open
```

启动后会打印本机地址，以及可以发给别人的局域网地址：

```
[trench] ready -> http://127.0.0.1:8080
[trench] LAN   -> http://192.168.1.23:8080
[trench] share the LAN url above; allow python through the firewall if asked
```

本机用浏览器打开 `http://127.0.0.1:8080` 即可。默认端口是 8080，若被占用会自动顺延到
8081、8082……（**终端里打印的才是实际端口**）。按 `Ctrl+C` 停止。

### 局域网联机与房号

服务端默认监听所有网卡，所以同一局域网里的**其它设备直接用浏览器打开终端打印的那条 `LAN`
地址**（形如 `http://192.168.1.23:8080`）就能打开游戏，不需要任何额外配置。

进入「多人模式」后按**房号（8 位数字）**分组，互不干扰：

- **自己创建房间**：点「创建房间」，服务器分配一个 8 位房号，HUD 右上角一直显示这个房号
  （`1958 0121` 这样分组显示，方便念给同学听）。把这个号发给大家即可。
- **加入房间**：点「加入房间」，填房主的 8 位房号（空格可省略），确认后才会开局；
  房号不存在会直接提示「房号不存在」，不会被塞进别人的房间。
- 主菜单会记住最近进过的房号，一键重进；页面上还列着当前**公开的房间**（人数 / 地图 / 阶段）。
- 同一房号里的玩家才会互相看见、互相打；不同房号的比赛完全隔离，比分和计分板也各自独立。
- 服务器同一时间只跑一张地图（`public/engine/combat.py` 只有一份世界状态）。如果别的房间正在另一张图上对局，
  你选的地图这一局会先让位——这时画面顶部会直接说明「「意大利小镇」正被其他房间占用，本局是「索姆河无人区」」，
  而不是默默换图。两个房间都停下后，下一局就会用上你选的地图。
- 房主离开、房间空掉之后，多人房号保留 2 分钟（够刷新页面重新进），单人练习房 15 秒就回收；
  房间满了（上限 24 间）时服务器会先回收最久没人用的空房间，而不是把人挡在门外——
  只有 24 间**都有真人**时才会提示「服务器上房间太多了，稍后再试」。

- **Windows 防火墙**：首次运行会弹出「是否允许 Python 访问网络」，必须点**允许**；
  点了取消会让外部设备完全连不进来，这是「同学连不上」最常见的原因。补救办法是到
  「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」里勾上 Python。
- 终端会列出**所有**非回环 IPv4 地址：装了 VMware / Hyper-V / WSL 的机器会多出虚拟网卡地址。
  请对照 `ipconfig` 里「无线局域网适配器 WLAN」或「以太网适配器」的那条，把正确的地址发给同学。
- 校园网、公共热点常开启 **AP 隔离**（同一网络下的设备彼此不可见）。遇到这种情况，让房主用
  电脑自建热点，同学先连热点，再打开上面那条地址。
- 端口被占用顺延时，记得把**实际端口**一起告诉同学（如 `http://192.168.1.23:8081`）。
- 主菜单新增的**「服务器地址」留空即自动**——自动连接当前页面的地址，这也是最常见的情况。
  只有在端口顺延后用旧地址、或同学打开的是自己电脑上的本地副本时，才需要手动填写房主的
  `IP` 或 `IP:端口`；填错时菜单下方会显示实际尝试连接的地址，方便排查。
- 安全提示：监听所有网卡后，免鉴权的角色模型上传接口（单文件上限 24MB）对同一网段的所有人开放，
  不要在不可信的网络上长期开着。
- 同一台机器开两个浏览器标签页也完全可以对局。

### 网页版联机（部署到 Vercel 等静态托管时，完全不需要服务器）

静态托管上没有任何服务端进程，但**多人照样能直接玩**：房间由**创建房间的那个玩家**在自己的
浏览器里运行（用的还是单机那套页内 Pyodide 引擎），其他人直接连到他。全程**不经过任何第三方
服务**——没有中转、没有账号、没有 key：

- **同一个浏览器多开标签页**：点「创建房间」后，把 8 位房号告诉另一个标签页，用「输入房号加入」
  填进去 → 部署即可。两个标签页走浏览器自带的 `BroadcastChannel`，瞬间即通。
- **不同的电脑**：用「邀请朋友」。房主点「生成邀请码」（`TFi1.` 开头的一大段文本），把它发给
  朋友；朋友的页面「用邀请码加入」→ 粘进去 → 得到回答码（`TFa1.` 开头），把回答码发回房主，
  房主粘进同一个框点「完成配对」。两页之间就建立了一条**点对点 WebRTC 直连**（`js/p2p.js`），
  对局数据只走这条直连。两个家庭宽带之间如果互相找不到（NAT），可以勾上「跨网络」开关加一个
  公共 STUN 服务器帮忙互相发现（只用来发现地址，数据不经过它）。
- **创建房间立刻就有房号**：点「创建房间」的瞬间就生成房号（不再等页内引擎启动），房号同时显示在
  HUD 右上角和「选择兵种」页面顶部；**点一下右上角的房号会复制邀请链接**（形如
  `https://你的站点/?code=1958 0121`），朋友打开就是加入这一局。
- **房主的浏览器就是这一局的权威**：命中、计分、复活、地图都在房主那边判定，其他人只是客户端。
  因此**每个房主都能选自己的地图，多个房间可以同时跑不同的地图**——这是自建服务端做不到的
  （`combat.py` 每个进程只有一份世界状态，所以服务端同一时刻只能跑一张图）。
- **暂停 / 离开**：按 **Esc** 打开菜单——「继续战斗」回到战场（暂停时房主这台电脑上的整局都会停住，
  别人看到画面停住并收到提示），「邀请朋友」当场发邀请码，「离开对局」回到主菜单（房主的房间会一起关掉，
  别人会收到明确提示）。Esc 永远不会把人卡在对局里出不来。
- 聊天、计分板、击杀提示、击杀播报都与局域网一致。房主关掉页面后，其他人会看到
  「与房主失去联系」，回主菜单重新加入别的房间即可。
- **自建中转仍然可选**：给网址加 `?relay=wss://你的中转:端口/mqtt`（例如内网的 mosquitto / EMQX /
  HiveMQ），或 `localStorage.setItem('tf.relay.broker', 'wss://…')` 固定下来。没有任何外部中转
  时页面也照常工作，因为默认根本不用它。
- **出问题时先看诊断页**：`/debug.html` 一次列出三个 `/api/*` 端点返回了什么、浏览器的能力
  （WebRTC / BroadcastChannel / WebAssembly…）、当前联机状态，还能做一次**本机点对点自测**
  （两条 WebRTC 连接互相发一句话）并复制成一份报告。
  自建服务端（下一节）仍然是想要固定大厅、共享角色库时更好的选择。

### 在受限的浏览器环境里运行

游戏本体不需要任何插件，但有两种浏览器环境会限制网页，已经都处理好了：

- **无法锁定鼠标的页面**（被嵌在 `iframe` 里、预览面板、sandbox 预览等）：
  指针锁定会被浏览器直接拒绝。这时游戏自动切到**「光标转向」**：把光标移到画面左右两侧转身、
  靠近上下边缘抬头/低头，按住鼠标拖动可精确瞄准，方向键同样能转身；
  开火、机瞄、下蹲、跳跃、换弹、技能一切照常。画面顶部会提示一次这个模式。
  **任何时候按 `Esc` 都能把光标还给你**（转为「已释放光标：点击画面继续」），
  再点一下画面就继续转向；鼠标锁定可用的页面里点一下则重新锁定。
  **想回到标准的鼠标锁定，就在新标签页里打开同一个地址。**
- **不能建立 WebSocket 的环境**（只允许普通 HTTP 的代理、部分预览面板）：
  客户端会自动改用 `POST /api/poll` 的**长轮询**通道，传的还是同一套消息，对局体验不变，
  只是菜单下方会注明正在使用轮询。
- 另外：主菜单的「服务器地址」填错或过期时，会自动回退到**当前页面的服务器**并在菜单下方说明；
  浏览器禁用本地存储、禁用 WebGL 的情况也会在加载页给出明确提示，而不是一直卡在载入画面。

### 三种模式

主菜单的三个按钮对应三种进入方式：

| 模式 | 说明 |
| --- | --- |
| 多人模式 | 联机团队死斗，默认只匹配真人；需要 AI 补位时打开「AI 机器人补位」开关（可选 4 / 6 / 8 / 12 个机器人） |
| 单人模式 | 一个人 + AI 队友，对抗 AI 敌军；机器人强制开启，开关变为只读的「单人固定」指示 |
| 设置模式 | 导入带蒙皮的 glTF/GLB，把模型骨骼映射到游戏关节、微调姿势，再上传共享给全场玩家选用 |

机器人走的是与人类玩家完全相同的服务端权威开火路径，不是特例逻辑。

**多人模式必须用房号进入**（创建或加入，见上一节）；单人模式与教程都在本浏览器内直接开局。

### 新手教程

主菜单的「新手教程」按钮（首次进入会轻微闪烁提示）带你走一遍完整流程：
移动 → 用鼠标转身 → 开火 → 机瞄 → 换弹 → 下蹲 / 跳跃 → 放技能 → 看计分板 / 语音 / 聊天 → 联机房号。
每一步都要**真的做出对应操作**才会打勾，右侧面板写着当前该做什么；
练习局是单人（不刷机器人，没人会打你），随时可以「跳过教程」或从面板里重新开始。
完成后会记在本机（`tf.profile`），之后不再自动提示。

### 本机存档（不需要任何 SQL 服务器）

**所有玩家资料只存在玩家自己的电脑上**，服务器不保存、也不下发任何个人数据：

- 玩家名、兵种、武器、皮肤、灵敏度、最近房号、教程状态、战绩统计（局数 / 胜场 / 击杀 / 阵亡 / 游戏时长）
  全部写在浏览器 `localStorage` 的 `tf.profile` 里；
- 「设置模式」页面下方会显示本机存档摘要（名字 / 最近房号 / 战绩 / 教程状态），
  可「导出存档」成 `trench-front-profile.json`，也可「清空本机数据」一键重置；
- 浏览器禁用本地存储时会退化为内存存储（当场可用，关掉页面即丢），并在页面里说明；
- 换电脑、换浏览器、清空站点数据都会让资料回到初始状态，这是预期行为，也是「没有任何服务器数据库」的代价。


### 自定义角色（设置模式）

1. 进入「设置模式」，选择带蒙皮的 `.glb` / `.gltf`（不支持 Draco / meshopt / KTX2，也不支持
   依赖外部 `.bin` 与贴图的 `.gltf`）。
2. 骨骼会自动按名字匹配到 13 个游戏关节（髋 / 脊柱 / 头 / 双肩 / 双肘 / 双腕 / 双膝 / 双踝），
   可以逐个手改；肩、肘、手不参与程序化动画，用偏移滑杆摆出持枪姿势。
3. 「缩放」「朝向」用于微调，归一化后角色会按 1.70 m 站高对齐游戏命中盒。
4. 「上传共享」会把模型与映射发给服务器（`POST /api/character`，单个文件上限 24MB），
   之后所有人在「共享角色」列表里都能「使用」；点「使用」即写入本机选择，进入对局后其他玩家看到的就是它。
5. 只点「仅本地保存」则映射与偏移只存在本机浏览器，不影响别人。

## 玩法规则

- 目标：先达到 **75 击杀**的一方获胜，或 **8 分钟**时间到时比分高的一方获胜。
- 阵亡后 3 秒可重新部署，重生时能免费更换兵种与武器。
- **呼吸回血**：连续 **8 秒**没有被子弹或爆炸命中，就会开始自动回血，并在 **8 秒内回满**
  （上限为自身最大生命值）。对该玩家造成任意伤害都会重置这个 8 秒计时；医疗包治疗区
  的回血与呼吸回血可以叠加。真人玩家与 AI 机器人都适用同一条规则。
- 视角：默认第一人称，按 `V` 可切到第三人称观察自己的角色模型（第一人称下看到的是
  与角色模型同源的双臂与武器；第三人称只移动相机，瞄准射线与命中判定完全不变）。
- 本作没有小地图：唯一能主动暴露敌人位置的手段是侦察兵的信号弹（被标记的敌人全队可见）。

## 部署

服务端是**单进程、单端口**的 aiohttp 应用，没有数据库、没有构建步骤，因此部署就是「装一个依赖、
跑一个命令」。仓库里已经备好三种落地方式：

**Docker（任何平台都能用）**

```bash
docker build -t trench-front .
docker run -p 8080:8080 trench-front
```

镜像基于 `python:3.12-slim`，只装 aiohttp，以非 root 用户运行，自带基于 `/api/health` 的
`HEALTHCHECK`。`PORT` 环境变量被显式读取（见下）。

**Render**：仓库根目录的 `render.yaml` 就是一份可直接用的 Blueprint——连接仓库、选择
Blueprint 即可（免费档会休眠，唤醒后第一次进入要等几秒）。健康检查路径 `/api/health`。
**这是最省事的「一键就能玩」方式**：它同时托管前端和游戏服务端。

**Heroku / Railway / Koyeb**：`Procfile` 已就位（`web: python server/server.py`），它们注入的
`PORT` 会被自动采用。

**Vercel（不需要任何后端，推荐）**

Vercel 的函数是「请求进、响应出」：没有 WebSocket，也没有常驻的 30 Hz 对局循环，所以游戏服务端跑不了
Vercel。但**对局本身也不需要服务端**——`public/engine/*.py` 就是服务端那同一份代码，页面用
**Pyodide**（WebAssembly 版 Python，随仓库一起部署在 `public/vendor/pyodide/`）把它拉进浏览器里跑，
`public/js/local.js` 负责驱动它。所以纯静态托管也是**能直接开打**的：单机 + 机器人，和自建服务端
玩起来是同一套规则、同一套弹道、同一套机器人 AI。

1. 在 Vercel 里 Import 这个仓库，Framework Preset 选 **Other**，Build Command / Output Directory
   都留空。
2. **把 Root Directory 设成 `public`**（Settings → Build and Deployment → Root Directory）。
   项目配置就在 `public/vercel.json`：`/api/*` 的三条接口重写到静态垫片文件，`/vendor/pyodide/*`
   带长缓存与正确的 MIME。仓库根目录那份 `vercel.json` 是给「Root Directory 留空」的老用法准备的，
   两套都留着，用的是哪套由 Root Directory 决定。
3. Deploy。打开网址 → 主菜单 → 单机/多人都可点「部署」：
   - 单机：浏览器内嵌引擎开局（浏览器里会显示「静态托管：对局由浏览器内嵌引擎运行」）。
   - 多人：**同样不需要服务器**——「创建房间」时这一局就在你的浏览器里跑，把房号 / 邀请链接
     发给朋友（同一浏览器多开标签页即可用房号进；不同电脑用「邀请朋友」的两个码直连），
     见上面「网页版联机」一节，多个房间可以同时跑不同地图。
     只有想要固定大厅、共享角色库（上传 GLB 给别人用）时，才需要下面 Render / Docker 的真服务端；
     那时在菜单的**「服务器地址」**里填它，或给网址加 `?server=your-app.onrender.com`。

静态托管上的接口由 `public/api/*.json` 垫片回答（`/api/health` 返回 `{"ok":true,"engine":"local"}`，
客户端据此知道「这个源没有服务端，改用页内引擎」）：菜单能开、内置角色都在，房间列表由页面从
中继上收集（垫片里是空的），角色上传需要真服务端（垫片会说明）。首次进入要下载约 12 MB 的 Python 运行时（之后走缓存），
只是第一次比平时慢几秒。

两个坑：**https 页面只能连 https 后端**（浏览器禁止 https 页面开 `ws://`），所以后端也要 https；
GitHub Pages 那种「放在子路径下」的托管需要注意——页面资源是绝对路径 `/js/...`，只在域名根目录下成立。

平台相关的行为：

- `PORT`：有该环境变量时**只用这一个端口**，不会再 8080→8081 顺延（顺延会让平台的端口映射 502）；
  本地没有 `PORT` 时仍然是 8080 起顺延 20 个端口。也可以用 `python server/server.py --port 9000`。
- 绑定 `0.0.0.0`（可用 `TRENCH_HOST` 覆盖），因为容器里绑 127.0.0.1 外面就进不来。
- HTTPS 页面自动使用 `wss://`（`main.js` 按 `location.protocol` 选择），WebSocket 被代理挡住时
  自动降级为 HTTP 长轮询，所以放在只允许普通 HTTP 的网关后面也能玩。
- **只能单实例**：房间、比分、地图都在内存里，而且服务器同一时刻只跑一张地图（`combat.py` 只有
  一份世界状态），所以不要开多副本 / 自动扩缩容，也不要开 sticky session——一个进程就是全部。
  （想要「一张地图同时被多个房间用」，走上面「网页版联机」那条路：房间在玩家浏览器里跑，
  每个房主各自一份世界状态。）
- 上传的共享角色模型写在 `public/shared/characters/`，容器重启即消失；要长期保存请挂载该目录。
- 静态资源分两档：模型/音效/`vendor`（合计 40 MB 左右）带 `Cache-Control: max-age=600` +
  ETag，第二次进图只发 304；`js`/`css`/`html`/`json` 仍然是 `no-store`，改完刷新即生效。
- 静态托管（Vercel）与自建服务端的区别只有一处：`/api/health` 的答复里带不带 `"engine":"local"`。
  带 → 页面用内嵌引擎（`public/js/local.js` + Pyodide），多人走玩家自己主持的房间（`public/js/relay.js`：
  同浏览器标签页用 BroadcastChannel，跨电脑用 `public/js/p2p.js` 的点对点直连，不需要任何服务）；
  不带 → 一切照旧走网络。
- 前后端可以分开部署：`public/js/api.js` 记住「`/api/...` 该问谁」。玩家在菜单里填了服务器
  地址（或网址带 `?server=`）之后，房间列表、共享角色库、角色上传都跟着那台服务器走；只有
  模型 / 音效 / `/shared/*.json` 还是从打开页面的地方加载。

## 技术要点

- **单一数据源**：所有数值都在 `public/shared/*.json`，服务端与客户端读同一份，不可能漂移。
  `python public/engine/combat.py` 可随时校验这份数据是否自洽。
- **一份服务端，两个宿主**：`room.py` / `game.py` / `combat.py` / `bots.py` 里没有任何 socket 代码，
  aiohttp 宿主（`server/server.py`）与页内宿主（`engine/host.py`，跑在 Pyodide 里）驱动的是同一个
  `Room`。所以「静态托管上的单机对局」不是另写一套简化版：弹道、伤害衰减、部位倍率、机器人 AI、
  地图投票、计分全部是同一份实现，网页上的表现和自建服完全一致。
- **出生点必有出路**：出生点在地图数据里本来就已经验证过「平地 + 头顶无遮挡」，但地图完全可能
  把一个碉堡摆在出生点正前方两米——出生即面壁，按住 W 寸步难行。现在 `random_spawn` 会把
  「面前 5 米可走」当作首选条件，被迫用的墙角出生点也会自动转向开阔方向，因此三个出生点仍然轮流使用，
  只是不再有人对着沙袋出生。
- **服务端权威**：命中判定、伤害、弹药、射速、技能冷却、计分全部由服务器决定，
  客户端只上报「我在哪」和「我朝哪开枪」，说别的都不作数。
- **客户端权威移动 + 服务端钳制**：移动手感在本机即时响应，服务器对位移做距离与边界校验后滑墙修正。
- **延迟补偿**：服务端为每个玩家维护一条 1 秒的位置环形缓冲（30Hz 采样一条，共
  `historyMs: 1000` 毫秒）。开火时把**所有目标**回滚到
  `ping/2 + interpDelayMs(120ms)` 之前的位置再做射线判定——也就是 shooter 客户端
  当时实际画在屏幕上的那个位置，所以「明明瞄准了却没伤害」不会再发生。
  细节：回滚窗口上限 `lagCompMaxMs: 220`；客户端自报的 RTT 在服务端硬钳到 240ms
  （虚报延迟只会让自己更容易被打中）；机器人不参与回滚（它们没有网络延迟）；
  复活与阵亡时会重置该玩家的缓冲，避免回滚跨越死亡打到旧位置。
- **外部骨骼角色**：上传的模型不可能认识游戏的关节命名，所以 `rig.js` 不做骨骼重定向，而是
  「进入时捕获 rest quaternion，每帧 `rest × delta`」——这是唯一跨模型都成立的写法。腿、脊柱、头
  由程序化步态驱动，肩 / 肘 / 腕不参与动画，留给用户的偏移滑杆摆持枪姿势。缩放靠 `Box3` 实测高度
  归一到 1.70 m 站高，与命中盒对齐。项目里没有 SkeletonUtils，蒙皮克隆自己实现（`clone(true)` 后
  按遍历顺序重绑 `Skeleton` + `boneInverses`）。模型的 id 随玩家状态一起下发（`state.ps[].sk`），
  远端玩家按它切换模型，模板懒加载完成后自动换装。
- **光照 / 材质健壮性**：地图的灯光、雾、天空色先过一遍 `lighting.js` 校验（缺项补默认值、
  颜色非法就丢弃、`fogFar > fogNear` 强制成立），所以地图文件写坏也不会黑屏；同时生成一张
  程序化天空的 PMREM 环境贴图挂到 `scene.environment`，供金属度较高的 glTF 枪械反射——
  导入的 PBR 模型金属度 1.0 而没有环境贴图时会渲染成全黑，这就是修掉的「黑模型」问题；
  完全没有贴图的金属材质会被压到 `metalness ≤ 0.6`。unlit 资源（`KHR_materials_unlit`）保持原样。
- **开火表现全部池化**：枪口焰、硝烟、弹壳都是预先建好的对象池（8 / 18 / 16 个），开火时只
  重新摆放，不分配、不销毁——900 发/分的自动武器也不会让 GC 抖动。枪口光用的是**常驻场景**的
  两盏 `PointLight`（平时强度 0）：三盏灯忽隐忽现会让 three.js 把整个世界重新编译一遍着色器，
  而常驻灯只是多一点点逐像素开销。镜头后坐只作用在**渲染用相机**上，准星与服务器共享的瞄准射线
  一个像素都不动，所以手感是「画面在抖」而不是「子弹乱飞」。
- **二次元渲染**：4 级阶梯渐变的 `MeshToonMaterial` + 倒壳描边 + 头发高光带；
  不开实时阴影，用脚下的深色圆片当假阴影；面部与立绘全部由 Canvas 程序化绘制，不依赖任何图片资源。
